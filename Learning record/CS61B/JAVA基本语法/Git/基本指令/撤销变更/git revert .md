`git revert` 是一个**撤销更改**的命令，它会创建一个新的提交，这个新提交的内容是用来撤销你指定提交所做的更改。

- **工作方式**：**添加**提交。它不会删除任何历史记录，而是通过创建一个新的“反向提交”来抵消旧提交的影响。
    
- **安全风险**：**低**。它不改变任何历史，只是增加了新的提交，因此可以在任何分支上安全使用，包括共享的远程分支。
    
- **最佳用途**：在**共享远程分支**上安全地撤销已发布的提交


`git revert` 命令的基本语法是：

```
git revert <提交>
```

---

### 语法详解

- **`git revert`**：这是命令本身，表示你要执行“撤销”操作。
    
- **`<提交>`**：这是你想要撤销的**目标提交**。你可以用任何可以引用提交的方式来指定它，最常见的是：
    
    - **提交哈希值**：`git revert a1b2c3d`。
        
    - **相对引用**：`git revert HEAD`（撤销当前最新的提交）、`git revert HEAD^`（撤销上一个提交）。
        
    - **分支名称**：`git revert main`（如果你在其他分支上，想撤销 `main` 分支的最新提交）。
        

---

### 举个例子

假设你的提交历史是这样的：`C1 -> C2 -> C3`。

如果你想撤销 `C2` 所做的更改，你的命令就是：

```
git revert C2
```

执行后，Git 会弹出一个编辑器让你填写新的提交信息，默认会帮你写好“Revert `C2`”，你可以修改或直接保存。

保存并退出后，你的提交历史会变成：`C1 -> C2 -> C3 -> C4`。这里的 `C4` 就是新创建的“撤销提交”，它的内容是 `C2` 的反向更改。

**重要提示**：当你使用 `git revert` 来撤销一个**合并提交**时，你需要使用 `-m` 参数来指定你想要保留哪一个父分支的历史。例如：`git revert -m 1 HEAD`，这告诉 Git 撤销这次合并，但保留**主线**（即第一个父分支）的历史。
