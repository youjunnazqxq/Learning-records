`git reset` 是一个**重写历史**的命令，它将分支的指针直接移动到之前的某个提交。这会使得被 `reset` 掉的提交像是从未发生过一样，从历史记录中消失。

- **工作方式**：**移除**提交。它会改变提交历史，将分支指针移回更早的提交，并丢弃之后的提交。
    
- **安全风险**：**高**。因为它会改变已发布的历史，如果你在共享分支上使用并强制推送，会使其他协作者的仓库历史与远程不一致，导致严重的冲突。
    
- **最佳用途**：只在**本地私有分支**上使用，用于撤销还未分享出去的提交。

你遇到的情况很正常，这是因为你输入的命令 `git reset local` 是一个**无效的命令**。

### 无效的原因

`git reset` 命令需要一个参数来告诉它**将分支重置到哪一个提交**。

- `git reset` 后面跟的参数应该是一个提交的引用，比如：
    
    - **分支名称**：`git reset main`（将当前分支重置到 `main` 分支的最新提交）
        
    - **相对引用**：`git reset HEAD~1`（将当前分支重置到上一个提交）
        
    - **提交哈希值**：`git reset a1b2c3d`（将当前分支重置到指定的提交）
        

在你这张图中，`local` 确实是一个分支名，但你当前的 `HEAD` **已经在 `local` 分支上**了。你正在尝试将 `local` 分支重置到它自己。这个操作没有意义，所以 Git 没有执行任何动作，也没有报错，只是保持了现状。

### 正确的做法

根据你的目标，你需要将 `local` 分支**重置**到**`pushed` 分支**指向的提交。

正确的命令应该是：

```
git reset pushed
```

这条命令会告诉 Git：

1. 找到 `pushed` 分支所指向的提交（`c2`）。
    
2. 将当前分支（`local`）的指针移动到 `c2`。
    

这样，`local` 分支就会回到 `c2`，与 `pushed` 分支在同一个位置。
