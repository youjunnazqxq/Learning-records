---

### `git cherry-pick` 是什么？

**`git cherry-pick`** 的作用是**将一个或多个提交，从一个分支“摘取”到另一个分支上**。

它不像 `git merge` 或 `git rebase` 那样合并整个分支的历史，而是允许你**精确地选择**你想要应用到当前分支的某一个或几个提交。

这个命令就像是：

- `git merge`：将整个“菜园子”都合并过来。
    
- `git rebase`：将你的“菜园子”移植到另一个地方。
    
- `git cherry-pick`：只“摘取”你想要的几个“樱桃”（cherry）。
    

---

### 语法

`git cherry-pick` 的基本语法很简单：

Bash

```
git cherry-pick <提交哈希值>
```

你也可以一次性摘取多个提交：

Bash

```
git cherry-pick <提交哈希值1> <提交哈希值2> ...
```

---

### 常见用途

`git cherry-pick` 通常用于以下场景：

1. **只修复一个 Bug**：当你在一个特性分支上发现了一个关键的 Bug 修复，但这个分支还没有准备好合并到主分支。你可以用 `cherry-pick` 将这个修复提交单独摘取到主分支上，从而快速发布修复。
    
2. **避免不必要的更改**：如果你想要合并一个分支上的某个功能，但不想合并它的所有历史记录，`cherry-pick` 是一个很好的选择。
    
3. **跨分支复制提交**：在一些高级工作流中，你可能需要在不进行常规合并的情况下，将某些提交从一个分支复制到另一个分支。
    

### 总结

`git cherry-pick` 是一个强大的工具，它允许你**精确地、有选择性地移动提交**。它不会改变原始分支的历史，而是在目标分支上**创建一个新的、内容相同的提交**。

在使用时，要注意它可能会导致冲突，你需要像解决合并冲突一样来解决它。这个命令非常适合用在那些你只需要某个提交而不需要整个分支历史的场景。
