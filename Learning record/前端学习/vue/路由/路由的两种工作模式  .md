
### 1. Hash 模式 (默认模式)

这是 Vue Router 的默认工作方式，也是最省心的模式。

- **URL 长相：** `http://localhost:8080/#/home`
    
- **关键特征：** 网址里有一个 `#` 号。
    
- **原理：**
    
    - `#` 及其后面的内容（`/home`）被称为 **Hash 值**。
        
    - **重要特性：** **Hash 值不会发给服务器！**
        
    - 当你按回车或刷新页面时，浏览器只把 `#` 前面的地址发给服务器请求 `index.html`。服务器根本不知道 `#` 后面写了什么。页面加载回来后，Vue 里的 JS 代码检测到 `#` 后面的变化，再自己决定显示哪个组件。
        
- **优点：** **兼容性极好**。因为不需要服务器配合，随便找个静态文件服务器扔上去就能跑，刷新也不会报错。
    
- **缺点：**
    
    - **丑**：网址里夹个 `#` 号，看起来不像正经官网。
        
    - **App 分享限制**：有些手机 App（比如某些支付回调或分享功能）会认为带 `#` 的 URL 是不合法的，导致功能无法使用。

### 2. History 模式 (推荐模式)

这是现代 Web 开发更常用的模式，因为它更专业。

- **URL 长相：** `http://localhost:8080/home`
    
- **关键特征：** 和普通网站一样，干干净净，没有 `#`。
    
- **原理：**
    
    - 利用了 HTML5 的新特性 `history.pushState`。它能让浏览器地址栏变化，但并不真的向服务器发起请求。
        
- **优点：** **美观**。符合用户习惯，看起来更像一个传统的服务端渲染网站。
    
- **缺点 (必须要懂的坑)：** **刷新会报 404 错误！** (除非后端配合)。
    

#### 为什么 History 模式刷新会 404？

这是面试常问的原理题，请务必理解：

1. 在 Hash 模式下：
    
    你刷新 http://a.com/#/home。浏览器实际上请求的是 http://a.com/。服务器把 index.html 给浏览器，浏览器再自己根据 # 处理路由。一切正常。
    
2. 在 History 模式下：
    
    你刷新 http://a.com/home。浏览器会老老实实地问服务器：“请给我一张叫 home 的网页”。
    
    服务器懵了： “我只有一个 index.html，没听说过什么 home 文件啊？”
    
    结果： 服务器直接返回 404 Not Found。
    

- 解决办法：
    
    这需要后端人员（或者运维配置 Nginx/Apache）的支持。
    
    需要在服务器端加一条规则：“如果你（服务器）找不到用户请求的那个文件，别报 404，直接把 index.html 返回给他就行了。”
    
    只要 index.html 一回来，Vue 启动了，它就能识别出 URL 里的 /home 并显示正确的页面。

### 3. 总结对比表

|**特性**|**Hash 模式**|**History 模式**|
|---|---|---|
|**URL 示例**|`domain.com/#/about`|`domain.com/about`|
|**美观度**|差 (带井号)|**好 (干净)**|
|**服务器压力**|此时 Hash 值不发给服务器|完整的 URL 都会发给服务器|
|**刷新页面**|**永远正常**|**如果不配后端，会报 404**|
|**底层原理**|`window.location.hash`|HTML5 `history.pushState`|
|**适用场景**|内部后台系统、简单的个人项目|官网、大型商业项目|

### 怎么切换模式？

在 `router/index.js` 里配置 `mode` 属性：

JavaScript

```
const router = new VueRouter({
  mode: 'history', // 不写默认是 'hash'
  routes: [...]
})
```
