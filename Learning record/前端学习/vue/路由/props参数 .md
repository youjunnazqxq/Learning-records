

### 1. 第一种写法：对象写法 (死数据)

JavaScript

```
// props: { a: 900 }
```

- **含义：** 不管路由怎么变，组件里收到的 `a` 永远是 `900`。
    
- **场景：** 这种写法**极少使用**。因为它传递的是**静态数据**（死数据）。通常用于给某个路由页面传递一些固定的配置开关。
    
- **组件里怎么接：** `props: ['a']`
    

---

### 2. 第二种写法：布尔值写法 (Params 专属)

JavaScript

```
// props: true
```

- **含义：** **“自动转发”**。
    
- **逻辑：** 只要你把这个设为 `true`，Vue 就会把路由路径里定义的 **Params 参数**（即 `path: 'detail/:id'` 里的 `id`），直接当作 props 传给组件。
    
- **局限性：** 它**只能**处理 Params 参数，无法处理 Query 参数（`?`后面的参数）。
    
- **场景：** 这是最常用的写法，用于处理 RESTful 风格的路径（如 `/detail/123`）。
    
- **组件里怎么接：** `props: ['id']`
    

---

### 3. 第三种写法：函数写法 (万能模式)

这也是截图里**正在生效**的那段高亮代码：

JavaScript

```
props(route) {
    return {
        id: route.query.id,
        title: route.query.title
    }
}
```

- **含义：** **“自定义加工”**。
    
- **逻辑：**
    
    1. Vue 会把当前的路由对象（`$route`）作为参数传给你（代码里的 `route`）。
        
    2. 你可以在函数里随意折腾：可以取 Query 参数，也可以取 Params 参数，甚至可以把两者结合，或者进行数学计算。
        
    3. **最终 return 什么对象，组件就会收到什么 props。**
        
- 截图中代码的作用：
    
    它明确指定去捞 Query 参数（route.query.id），然后把它赋值给 id 传给组件。
    
- **场景：**
    
    - 当你想把 Query 参数（`?id=666`）转成 props 时（因为布尔值写法不支持 Query）。
        
    - 当你需要对参数进行类型转换（比如把字符串 "100" 转成数字 100）再传给组件时。
        

---

### 总结一下

|**写法**|**代码示例**|**适用场景**|**灵活性**|
|---|---|---|---|
|**对象写法**|`props: {a:1}`|传**固定值**（极少用）|低|
|**布尔写法**|`props: true`|传 **Params 参数**（最常用）|中|
|**函数写法**|`props($route){...}`|传 **Query 参数** 或 **混合数据**|**高 (万能)**|

你截图中的代码展示的是**第三种（函数写法）**，目的是为了让组件能以 Props 的形式接收到 URL 中 `?` 后面的 Query 参数。
