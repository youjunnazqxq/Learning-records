。

### 1. 默认模式：PUSH（追加）

如果不加 replace，默认就是 push 模式。

这就像是**“往盘子堆上加一个新盘子”**。

- **操作过程：**
    
    1. 你打开了 **页面A**。（盘子堆：A）
        
    2. 点击链接去了 **页面B**。（盘子堆：A -> B）
        
    3. 点击链接去了 **页面C**。（盘子堆：A -> B -> C）
        
- 结果：
    
    当你点浏览器“后退”按钮时，浏览器拿掉最上面的盘子 C，你会回到 B。再点后退，回到 A。
    
    （这是我们最习惯的操作方式，因为历史记录都被保留了）。
    

---

### 2. REPLACE 模式（替换）

如果在 <router-link> 上加了 replace 属性。

这就像是**“把当前最上面的盘子扔掉，换成一个新的”**。

- **操作过程：**
    
    1. 你打开了 **页面A**。（盘子堆：A）
        
    2. 点击链接去了 **页面B**。（盘子堆：A -> B）
        
    3. **【关键点】** 在页面 B，你点击了一个带 `replace` 的链接去 **页面C**。
        
        - 浏览器会说：“好，我把当前的 B 扔掉，把 C 放进去。”
            
        - 现在的盘子堆变成了：**A -> C** （注意：B 不见了！）
            
- 结果：
    
    当你现在点浏览器“后退”按钮时，C 被拿掉，你直接回到了 A！
    
    页面 B 就像从未存在过一样，它的历史记录被“替换”掉了。
    

---

### 3. 什么时候需要用 Replace？（经典场景）

你可能会问：“为什么要故意让人回不去呢？”

**最经典的场景是：登录页面。**

想象一下这个流程：

1. 用户在 **首页**。
    
2. 用户点击 **登录页**。
    
3. 用户输入账号密码，登录成功，跳转到 **后台中心**。
    

如果不使用 Replace：

用户在“后台中心”点击后退按钮 ——> 又回到了“登录页”。

这就很尴尬了，用户已经登录了，不应该再看到登录框。

如果使用 Replace：

在登录成功跳转时使用 replace。

用户在“后台中心”点击后退按钮 ——> 直接回到“首页”。

（登录页的历史记录被后台中心替换掉了，完美！）

### 4. 代码怎么写？

**写法非常简单，只需要加一个单词：**

HTML

```
<router-link to="/test">去测试页</router-link>

<router-link replace to="/test">去测试页</router-link>
```

### 总结

- **Push (默认)：** 留后路。走一步记录一步，点后退能回去。
    
- **Replace：** 不留后路。把当前这一页的历史记录抹掉，用新页面顶替它，点后退就回不来了。
