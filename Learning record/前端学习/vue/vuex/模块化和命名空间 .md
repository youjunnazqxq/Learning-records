
### 📝 Vuex 模块化与命名空间总结

#### 1. 模块化 (Modules)

- **背景**：当应用变大时，如果所有状态都写在一个 `index.js` 里，代码会变得极其臃肿且难以维护。
    
- **定义**：将 Store 分割成多个**模块 (module)**，每个模块拥有自己的 `state`, `mutation`, `action`, `getter`。
    
- **代码结构**：
    
    JavaScript
    
    ```
    // store/index.js
    import user from './modules/user'
    import cart from './modules/cart'
    
    export default createStore({
      modules: {
        user, // 挂载 user 模块
        cart  // 挂载 cart 模块
      }
    })
    ```
    

#### 2. 命名空间 (Namespaced)

- **背景**：默认情况下，模块内部的 Action/Mutation 是注册在**全局**的。如果不同模块有同名方法（如都叫 `add`），调用时会同时触发，导致逻辑混乱。
    
- **定义**：通过设置 `namespaced: true`，让模块拥有独立的“封装环境”。
    
- **核心配置**：
    
    JavaScript
    
    ```
    // store/modules/user.js
    export default {
      namespaced: true, // 👈 关键点：开启命名空间
      state: { name: 'Alice' },
      mutations: {
        CHANGE_NAME(state) { ... } // 实际注册名为 'user/CHANGE_NAME'
      }
    }
    ```
    

#### 3. 开启命名空间后的调用方式 (重点)

一旦开启命名空间，访问该模块时必须带上 **模块名路径**。

|**操作类型**|**原始调用方式 (Raw)**|**路径格式**|
|---|---|---|
|**State**|`this.$store.state.user.name`|**注意**：State 结构始终是嵌套的，不需要斜杠|
|**Getters**|`this.$store.getters['user/upperName']`|`模块名/getter名`|
|**Mutations**|`this.$store.commit('user/CHANGE_NAME')`|`模块名/mutation名`|
|**Actions**|`this.$store.dispatch('user/login')`|`模块名/action名`|

#### 4. 辅助函数简写 (mapHelpers)

使用 `mapState`, `mapMutations` 等时，可以将**模块名作为第一个参数**，代码会非常简洁。

JavaScript

```
<script>
import { mapState, mapMutations } from 'vuex'

export default {
  computed: {
    // ❌ 不用命名空间的写法 (麻烦)
    // ...mapState({ name: state => state.user.name })

    // ✅ 使用命名空间的写法 (推荐)
    // 参数1: 模块名, 参数2: 字段数组
    ...mapState('user', ['name', 'age']) 
  },
  methods: {
    // 映射为 this.CHANGE_NAME()，调用时自动带上 user/ 前缀
    ...mapMutations('user', ['CHANGE_NAME'])
  }
}
</script>
```

#### 💡 一句话记忆

- **模块化 (Modules)** 是为了**分类**（把大仓库拆成生鲜区、家电区）。
    
- **命名空间 (Namespaced)** 是为了**隔离**（给每个区加门禁，想办事必须喊“生鲜区/拿苹果”）。
