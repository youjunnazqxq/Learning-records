

> 场景：子组件是一个 “按钮组件 (Child)”，父组件是 “App (Parent)”。
> 
> 目标：用户点击子组件里的按钮，要把 “你好，我是子组件的数据” 这句话传给父组件，并在父组件的控制台打印出来。

---

### 第一部分：子组件 (Child.vue) —— 它是“发送方”

子组件的任务非常明确：**在特定的时机（比如点击时），把数据“发射”出去。**

#### 1. 模板 (HTML)

你需要有一个触发机制，最常见的就是 `click` 事件。

HTML

```
<template>
  <div class="child">
    <h2>我是子组件</h2>
    <button @click="sendData">点击我，把数据传给父组件</button>
  </div>
</template>
```

#### 2. 逻辑 (Script)

这是核心。使用 `$emit` 发射信号。

JavaScript

```
<script>
export default {
  name: 'Child',
  data() {
    return {
      msg: '你好，我是子组件的数据'
    }
  },
  methods: {
    sendData() {
      // 核心代码：this.$emit(事件名, 参数1, 参数2...)
      // 1. 'atguigu': 这是咱们约定的“暗号”（自定义事件名）。
      // 2. this.msg: 这是要运送的“货物”（数据）。
      this.$emit('atguigu', this.msg)
      
      console.log('子组件：我已经把信号发射出去了！')
    }
  }
}
</script>
```

---

### 第二部分：父组件 (App.vue) —— 它是“接收方”

父组件的任务是：**提前在该组件标签上安装“监听器”，一旦听到信号，马上执行对应的处理函数。**

父组件有两种写法，**细节非常重要**。

#### 写法一：在模板中直接绑定 (最常用、最推荐)

这种写法清晰明了，也是 90% 的场景下会用的方式。

HTML

```
<template>
  <div class="app">
    <h1>我是父组件</h1>
    
    <Child @atguigu="handleEvent"/>
  </div>
</template>

<script>
import Child from './Child.vue'

export default {
  components: { Child },
  methods: {
    // 这个 data 就是子组件传过来的 msg
    handleEvent(data) {
      console.log('父组件：我收到了数据 ——', data)
      // 此时 this 指向父组件，你可以把数据存起来
      // this.info = data
    }
  }
}
</script>
```

---

#### 写法二：在 JS 中通过 ref 绑定 (更灵活)

这种写法适合**动态绑定**（比如：等页面加载完 3 秒后再开始接收消息），但这里就是**如果你不小心，this 就会出错**的地方。

HTML

```
<template>
  <div class="app">
    <h1>我是父组件</h1>
    <Child ref="student"/>
  </div>
</template>

<script>
import Child from './Child.vue'

export default {
  components: { Child },
  methods: {
    test(data) {
      console.log('methods定义的方法拿到数据：', data)
    }
  },
  mounted() {
    // 此时组件挂载完毕，可以找到 this.$refs.student
    
    // --- ❌ 错误演示 (坑) ---
    // this.$refs.student.$on('atguigu', function(data) {
    //    console.log(this) // 输出 Child 组件实例！
    //    this.info = data  // 报错！因为 Child 组件里没有 info 这个变量
    // })

    // --- ✅ 正确演示 1：配合 methods (推荐) ---
    // 直接把 methods 里的函数引用传进去，this 自动指向父组件
    this.$refs.student.$on('atguigu', this.test)

    // --- ✅ 正确演示 2：使用箭头函数 (灵活) ---
    // 箭头函数的 this 找外层（mounted），所以是父组件
    this.$refs.student.$on('atguigu', (data) => {
       console.log('箭头函数拿到数据：', data)
       console.log(this) // 输出 App 组件实例，正确！
    })
  }
}
</script>
```

### 第三部分：全流程图解 (总结)

为了让你脑海里有个动态的画面，整个过程是这样的：

1. **用户操作**：点击了 **子组件** 的按钮。
    
2. **子组件反应**：执行 `sendData` 方法，调用 `this.$emit('atguigu', '数据')`。
    
    - _潜台词：“喂！代号 `atguigu` 的事件触发了！带着数据！”_
        
3. **Vue 介入**：Vue 检查父组件的模板或 `$on` 记录，发现 **父组件** 正在监听 `atguigu`。
    
4. **父组件反应**：
    
    - 如果是模板绑定 (`@`)：直接执行父组件 `methods` 里的 `handleEvent`。
        
    - 如果是 ref 绑定 (`$on`)：执行回调函数（注意箭头函数确保了 `this` 在父组件）。
        
5. **结果**：父组件拿到了数据，完成了通信。
    

#### . 触发与解绑（子组件怎么做）

- **触发事件**：
    
    JavaScript
    
    ```
    // 发送信号，第二个参数是传递的数据
    this.$emit('atguigu', 'Tom')
    ```
    
- **解绑事件**：
    
    JavaScript
    
    ```
    this.$off('atguigu') // 解绑单个
    this.$off()          // 解绑所有
    ```
    

### 四. ⚠️ 三个必须死磕的“坑”（重点）

1. **关于 `this` 指向（使用 `$on` 时）**
    
    - **严禁**：直接写 `function() {}`（普通函数）。
        
        - _原因_：`$emit` 内部运行时会强行把 `this` 指向**子组件实例**，导致你无法操作父组件的数据。
            
    - **必须**：使用 **箭头函数 `() => {}`** 或直接引用 **`methods` 中的方法**。
        
        - _原因_：箭头函数的 `this` 永远指向定义它的地方（即**父组件**）。
            
2. **关于原生事件**
    
    - 如果你给组件标签绑定 `@click`，Vue 默认会以为这是一个叫 "click" 的自定义事件。
        
    - **解决**：添加 `.native` 修饰符，如 `<Student @click.native="show"/>`，告诉 Vue 这是原生的 DOM 点击事件。
        
3. **关于回调函数的位置**
    
    - 虽然事件是在子组件里触发的，但**处理事件的回调函数逻辑是写在父组件里的**（因为目的是修改父组件的数据）。
