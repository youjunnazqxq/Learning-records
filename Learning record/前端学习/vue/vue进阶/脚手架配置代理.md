
# 📝 Vue 脚手架代理配置笔记

### 0. 核心目的

解决开发环境下的 **跨域 (CORS)** 问题。让浏览器把请求发给同源的“本地开发服务器”，再由服务器转发给“后端服务器”。

---

### 1. 方法一：简易全局代理

**适用场景：** 后端只有一台服务器，且不需要重写路径。

**配置：**

JavaScript

```
module.exports = {
  devServer: {
    // 直接写目标服务器地址
    proxy: 'http://localhost:5000' 
  }
}
```

**⚠️ 核心记忆点（坑点）：**

- **优先匹配前端资源：** 如果你请求 `/index.html` 或者 `/public` 文件夹里有的文件，代理会直接返回前端文件，**不会**转发给后端。只有前端没有的资源，才会转发。
    
- **局限性：** 只能配置一个代理，无法控制特定路径才走代理。
    

---

### 2. 方法二：灵活多路代理（推荐）

**适用场景：** 有多个后端接口，或者需要精细控制路径（如重写路径）。

**配置：**

JavaScript

```
module.exports = {
  devServer: {
    proxy: {
      // 1. 匹配规则：以 '/api1' 开头的请求走这个代理
      '/api1': { 
        target: 'http://localhost:5000', // 目标地址
        changeOrigin: true,              //控制 Host 头（见下文）
        pathRewrite: { '^/api1': '' }    // 路径重写（重要！）
      },
      // 2. 配置第二个代理
      '/api2': {
        target: 'http://localhost:5001',
        changeOrigin: true,
        pathRewrite: { '^/api2': '' }
      }
    }
  }
}
```

**✅ 核心优势：**

- 可以配置多个代理（`/api1` 去服务器A，`/api2` 去服务器B）。
    
- 可以灵活控制哪些请求走代理（必须带前缀）。
    

---

### 3. 三大关键参数详解 (背诵点)

|**参数名**|**作用**|**详细逻辑 (图片重点)**|
|---|---|---|
|**`target`**|**去哪儿**|代理转发的目标基础路径。|
|**`pathRewrite`**|**去皮**|`{ '^/api1': '' }`<br><br>  <br><br>**必配！** 否则后端收到的请求会多出 `/api1` 这个前缀，导致 404。|
|**`changeOrigin`**|**撒谎**|**`true` (默认)**: 代理服务器会“撒谎”，把请求头中的 Host 改为**目标服务器**的地址 (如 `localhost:5000`)。<br><br>  <br><br>**`false`**: 如实告知，Host 保持为**前端**地址 (如 `localhost:8080`)。<br><br>  <br><br>_注：通常设为 true 以绕过后端对 Host 的检查。_|

---

### 🚀 一句话总结回忆

- **简单版**是“备胎逻辑”（前端找不到才找后端）；
    
- **复杂版**是“精准路由”（前缀匹配 + 路径重写 + 伪造 Host），开发中**99%的情况用方法二**。
