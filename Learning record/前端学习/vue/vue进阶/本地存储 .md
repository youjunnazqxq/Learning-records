根据你提供的图片内容，我为你总结了 **WebStorage (浏览器本地存储)** 的核心知识点。

你可以把它理解为**浏览器自带的一个“小型数据库”**，专门用来帮你在用户的电脑上存一些数据。

以下是结构化的总结，方便你记忆：

### 1. 核心特点

- **空间大小**：一般支持 **5MB** 左右（比 Cookie 大得多）。
    
- **存储内容**：以 **键值对 (Key-Value)** 的形式存储，且**值必须是字符串**。
    
- **实现方式**：通过 `window.localStorage` 和 `window.sessionStorage` 属性来实现。
    

---

### 2. 两大存储类型的区别 (面试/考试重点)

这两兄弟用法完全一样，唯一的区别在于**“活多久” (生命周期)**：

|**特性**|**LocalStorage (本地存储)**|**SessionStorage (会话存储)**|
|---|---|---|
|**生命周期**|**永久有效**|**窗口关闭即消失**|
|**消失条件**|除非用户手动清除或代码调用清理，否则一直存在。|浏览器窗口或标签页关闭后，数据自动销毁。|
|**应用场景**|记住登录状态、主题颜色偏好、购物车数据。|表单临时数据、单次访问的临时状态。|

---

### 3. 四大核心 API (CRUD 操作)

这里的 `xxxxStorage` 指代 `localStorage` 或 `sessionStorage`，它们的方法是一模一样的：

- 存 (Create/Update):
    
    xxxxStorage.setItem('key', 'value')
    
    (如果 key 已存在，则是修改；如果不存在，则是新增)
    
- 取 (Read):
    
    xxxxStorage.getItem('key')
    
- 删 (Delete):
    
    xxxxStorage.removeItem('key')
    
- 清空 (Clear):
    
    xxxxStorage.clear() (慎用，会把所有数据删光)
    

---

### 4. 必须要知道的“坑” (注意事项)

图片中的 **备注** 部分非常关键，实际开发中经常遇到：

1. 空值处理：
    
    如果你用 getItem 去找一个不存在的 key，它不会报错，而是返回 null。
    
2. JSON 解析的安全性：
    
    JSON.parse(null) 的结果依然是 null。
    
    - 这很好！这意味着你不需要专门为了防止 `null` 而写很多 `if` 判断，直接解析通常是安全的。
        

---

### 💡 补充一个实战小技巧

因为 WebStorage **只能存字符串**，如果你想存一个**对象 (Object)**（比如一个 `user` 对象），必须搭配 JSON 方法使用：

- **存的时候**：`JSON.stringify(obj)` —— 把对象转成字符串再存。
    
- **取的时候**：`JSON.parse(str)` —— 把取出来的字符串转回对象。
