

### 一、 什么是回流（Reflow / 重排）？

当 DOM 的变化影响了元素的**几何信息**（例如宽度、高度、位置、隐藏/显示状态等），浏览器需要重新计算这些元素的几何属性，并将其重新安置在页面中的正确位置。这个重新计算并排版的过程，就叫做**回流**。

由于牵一发而动全身（一个元素的位置变化可能会影响父元素、兄弟元素甚至整个文档树的布局），**回流的性能开销非常大**。

#### 常见触发场景：

- **页面首次渲染**（不可避免）。
    
- **浏览器窗口尺寸改变**（`resize` 事件）。
    
- **DOM 树结构变化**：添加、删除、移动可见的 DOM 元素。
    
- **元素尺寸或位置变化**：修改 `width`、`height`、`padding`、`margin`、`border`、`position` 等。
    
- **内容发生变化**：例如文本内容被替换，或者图片加载完成撑开/改变了父容器的大小。
    
- **获取特定的布局属性**：当你在 JavaScript 中读取 `offsetTop`、`offsetLeft`、`offsetWidth`、`clientHeight`、`scrollTop` 等属性，或者调用 `getComputedStyle()` 时。为了保证返回值的准确性，浏览器会强制清空渲染队列，立即触发一次回流。

### 二、 什么是重绘（Repaint）？

当一个元素的**外观、风格发生改变**，但完全**没有影响到它的布局和几何尺寸**时，浏览器只需要把这个元素的新样式重新画在屏幕上。这个过程就叫做**重绘**。

因为不需要重新计算位置和大小，**重绘的性能开销比回流要小得多**。

#### 常见触发场景：

- 修改字体颜色：`color`。
    
- 修改背景颜色：`background-color`。
    
- 修改元素的可见性：`visibility: hidden`（注意，如果是 `display: none` 则会触发回流，因为它改变了布局）。
    
- 修改边框样式或阴影：`border-style`、`box-shadow`、`border-radius` 等。

### 三、 核心总结与避坑指南

1. **包含关系**：**回流一定会触发重绘，但重绘不一定会触发回流。**
    
2. **性能优化建议**：在实际开发中，我们应该尽量减少回流的次数。
    
    - **合并样式修改**：不要一条条地用 JS 修改元素的 style，最好一次性修改 `className` 或者使用 `cssText`。
        
    - **批量操作 DOM**：如果需要大量添加 DOM 节点，可以使用 `DocumentFragment` 在内存中拼装好，再一次性插入到页面中。
        
    - **脱离文档流**：对于需要频繁做动画的元素，将其设置为 `position: absolute` 或 `fixed`，这样它的回流就不会影响到页面上的其他元素。
        
    - **利用硬件加速**：在上一题提到的 CSS3 动画中，优先使用 `transform`（如 `translate` 代替 `top`/`left`）和 `opacity` 来实现动画。现代浏览器会对这两个属性开启 GPU 硬件加速，它们**既不会触发回流，也不会触发重绘**，性能极佳。
