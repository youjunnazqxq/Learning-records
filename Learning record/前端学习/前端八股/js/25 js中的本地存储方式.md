在前端开发中，浏览器本地存储是非常高频使用的功能。经典的本地存储方式主要有三种：**Cookie**、**localStorage** 和 **sessionStorage**。现代浏览器还提供了一个用于存储大量结构化数据的微型数据库 **IndexedDB**。

这里我主要为你深度解析最常用的前三种，从特点、区别到实际业务场景进行梳理。

### 1. Cookie

Cookie 是最古老的本地存储机制，它的本意其实**不是为了单纯的本地存储，而是为了解决 HTTP 协议无状态的问题**（即让服务器知道两次请求是不是同一个用户发出的）。

- **特点与机制**：
    
    - **容量极小**：通常只有 4KB 左右。
        
    - **自动携带**：这是它最大的特点。只要满足同源策略，每次前端发起 HTTP 请求时，浏览器都会**自动**把 Cookie 放在请求头（Request Headers）中发送给服务器。
        
    - **生命周期**：可以通过设置 `Expires` 或 `Max-Age` 属性来决定何时过期。如果不设置，它就是一个“会话级” Cookie，关闭浏览器窗口就会消失。
        
- **应用场景**：
    
    - **用户身份凭证（Token/Session ID）**：登录后，服务器返回一个凭证存在 Cookie 里，之后每次请求都会自动带上，服务器借此认出你是谁。
        
    - **记住密码/自动登录**：设置了较长过期时间的 Cookie。
        
    - **用户行为跟踪**：比如电商网站用于推荐算法的用户标识。
        

### 2. localStorage

HTML5 引入的 Web Storage API 之一，专门为了解决 Cookie 存储量太小且每次请求都被强制携带的痛点而生。

- **特点与机制**：
    
    - **容量较大**：通常在 5MB 左右（不同浏览器略有差异）。
        
    - **不参与网络通信**：它仅仅存储在本地浏览器中，绝不会自动跟随 HTTP 请求发送到服务器，节省了带宽。
        
    - **生命周期**：**持久化存储**。除非用户手动在浏览器清除缓存，或者用 JavaScript 代码主动清除（`localStorage.clear()` 或 `removeItem()`），否则数据永远不会过期。
        
- **应用场景**：
    
    - **长期偏好设置**：比如用户选择了“暗黑模式”，或者侧边栏的展开/收起状态。
        
    - **性能优化缓存**：缓存一些体积较大、不常变动的业务基础数据（如省市区列表），减少接口请求。
        
    - **非登录状态下的购物车**：用户没登录时加购的商品，可以先存在 localStorage 中，登录后再同步到服务器。
        

### 3. sessionStorage

同样是 HTML5 引入的 Web Storage API，它的 API 用法（`setItem`, `getItem` 等）和 localStorage 完全一模一样，唯一的区别在于**生命周期**。

- **特点与机制**：
    
    - **容量与通信**：和 localStorage 一样，约 5MB，且不随 HTTP 请求发送。
        
    - **生命周期**：**标签页级别的会话存储**。数据仅在当前浏览器标签页（Tab）下有效。当你关闭这个标签页时，数据就会被销毁。
        
    - _注意一个冷知识：如果你通过点击链接打开了一个新标签页，新标签页会复制一份原来页面的 sessionStorage，但从此之后两者的修改互不影响。_
        
- **应用场景**：
    
    - **敏感或临时状态**：比如多步表单（注册步骤 1/2/3），刷新页面时数据不丢，但关闭标签页就作废，避免隐私泄露。
        
    - **从列表页到详情页的传参**：如果不想把参数拼在 URL 上，可以暂存在 sessionStorage 里，详情页用完且页面关闭后自动清理。

### 📝 核心区别速查表

|**特性**|**Cookie**|**localStorage**|**sessionStorage**|
|---|---|---|---|
|**存储大小**|约 4KB|约 5MB|约 5MB|
|**生命周期**|可自定义过期时间。不设置则随浏览器关闭销毁|永久有效，直到手动清除|仅在当前标签页有效，关闭标签页销毁|
|**与服务端的通信**|每次 HTTP 请求**自动携带**在 Header 中|纯前端存储，**不参与**通信|纯前端存储，**不参与**通信|
|**易用性**|原生 API (`document.cookie`) 难用，需要自己封装解析|API 友好 (`setItem`, `getItem`)|API 友好 (`setItem`, `getItem`)|
