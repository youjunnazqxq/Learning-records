这份文档非常清晰地拆解了 JavaScript 事件循环（Event Loop）的核心机制。以下是为你提炼的核心总结：

### 事件循环的核心概念

- JavaScript 是一门单线程语言，它通过事件循环机制来实现单线程下的非阻塞运行。
    
- 代码执行时，同步任务会直接进入主线程（主执行栈）立刻执行，而异步任务则会被推入任务队列中等待。
    
- 当主线程任务清空后，引擎会去任务队列中读取任务并推入主线程执行，这个不断重复的过程就是事件循环。
    

### 宏任务与微任务的执行规律

- 为了精确控制异步代码的执行顺序，异步任务被细分为了**微任务（Microtask）**和**宏任务（Macrotask）**。
    
- **微任务**优先级极高，包含 `Promise.then`、`MutationObserver`、`process.nextTick` 等。
    
- **宏任务**时间粒度较大，包含最外层的同步代码（`script`）、`setTimeout`、`setInterval`、UI 渲染等。
    
- **执行机制**：引擎每次执行完**一个**宏任务后，都会立刻去查看微任务队列，并将里面**所有**的微任务依次执行完毕，然后再去执行下一个宏任务。
    

### `async` 与 `await` 的本质

- `async` 用于声明一个异步方法，它在底层默认返回一个 Promise 对象。
    
- `await` 具有**阻塞**特性。当代码执行到 `await` 时，它会阻塞该函数内部排在它后面的代码（本质上是把后面的代码加入了微任务队列）。
    
- 阻塞发生后，引擎会先跳出当前的 `async` 函数，去执行外部剩余的同步代码，等外部同步代码执行完毕，再回过头来执行刚才被阻塞的代码。
