这是一个非常经典且在面试和实际开发中极其高频的问题。

在 JavaScript 中，最著名的笑话莫过于 `0.1 + 0.2 !== 0.3`（它的真实结果是 `0.30000000000000004`）。这其实不是 JavaScript 的 Bug，而是所有采用**IEEE 754 双精度浮点数标准**的编程语言都会面临的基础物理/数学限制。

### 一、 为什么会产生精度丢失？

要理解为什么会丢失，我们需要看看计算机底层是如何处理数字的：

1. **十进制到二进制的转换**：我们输入的是十进制数（0.1, 0.2），但计算机底层只能用二进制（0 和 1）来进行计算。
    
2. **无限循环的小数**：很多在十进制下看起来非常“干净”的小数（比如 0.1），一旦转换成二进制，就会变成**无限循环小数**（0.1 的二进制是 `0.00011001100110011...`）。
    
3. **内存截断（罪魁祸首）**：JS 使用的 IEEE 754 64位标准中，留给小数部分（尾数）的空间只有 **52 位**。面对无限循环小数，计算机只能在第 52 位强行“截断”，这就产生了极其微小的误差。
    
4. **误差放大**：当你把两个已经被截断带有微小误差的数字（0.1 和 0.2）进行加减乘除时，这些底层的二进制误差就会发生叠加，最终在转换回十进制展示时，暴露出了长长的尾巴（比如 `...000004`）。

### 二、 在业务中如何解决这个问题？

根据你具体的业务场景，解决精度丢失通常有以下 4 种层级的方案：

#### 1. 仅用于页面展示：`toFixed()`

如果你只是为了在 UI 上展示两位小数的价格，而不涉及后续的计算，直接使用 `toFixed()` 截取即可。

- **注意**：`toFixed()` 返回的是**字符串**。并且它的底层存在“四舍五入”的诡异表现（其实是“银行家舍入”），在极其严格的金融场景下要慎用。
    

JavaScript

```
const price = 0.1 + 0.2; 
console.log(price.toFixed(2)); // 输出字符串 "0.30"
```

#### 2. 用于逻辑判断：`Number.EPSILON`

如果你需要**比较**两个浮点数是否相等，不要用 `===`，而是要引入一个极小的误差容忍值 `Number.EPSILON`（JS 引擎能够识别的最小精度差）。

JavaScript

```
function isEqual(a, b) {
  // 如果两数之差的绝对值，小于这个最小误差，我们就认为它们相等
  return Math.abs(a - b) < Number.EPSILON;
}

console.log(isEqual(0.1 + 0.2, 0.3)); // true
```

#### 3. 简单的运算：整数放大法（乘法转整数）

因为 JavaScript 在处理安全范围内的**整数**（不超过 `Number.MAX_SAFE_INTEGER`）时是绝对精确的。所以对于普通的金额计算，我们可以**先放大变成整数，算完再缩小**。

JavaScript

```
// 比如计算 0.1 + 0.2
function add(num1, num2) {
  // 1. 找到小数位数最多的那个数，决定放大倍数 (这里放大10倍即可)
  const m = 10; 
  // 2. 全部变成整数运算：(1 + 2) / 10
  return (num1 * m + num2 * m) / m; 
}
console.log(add(0.1, 0.2)); // 0.3
```

- **缺陷**：当数字极其巨大或小数位数极多时，这种简易封装依然可能溢出或出错。
    

#### 4. 终极方案（商业/金融级应用）：使用第三方数学库

在真实的电商、金融后台管理系统中（比如你正在开发的管理系统），绝不能自己手写放大逻辑去处理钱。**业界标准是直接引入成熟的第三方库**。这些库底层通过将数字转化为字符串或数组进行逐位运算，彻底规避了浮点数限制。

最常见的库有：

- **`decimal.js`**：功能最全面，支持超高精度，但体积稍大。
    
- **`bignumber.js`**：专注于金融和高精度计算，API 丰富（常用于区块链）。
    
- **`big.js`**：`bignumber.js` 的极简版，体积小巧，非常适合普通的电商网页计算。
    

JavaScript

```
// 引入 big.js 后的用法示例
import Big from 'big.js';

// 将数字转成 Big 对象进行运算
const x = new Big(0.1);
const y = new Big(0.2);
const result = x.plus(y); // 加法

console.log(result.toString()); // 精确输出 "0.3"
```
