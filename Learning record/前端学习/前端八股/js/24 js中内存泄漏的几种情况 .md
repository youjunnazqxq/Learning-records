

### 1. 意外的全局变量

在 JavaScript 中，如果没有使用 `var`/`let`/`const` 声明变量，或者在非严格模式下的全局函数中误用 `this`，变量就会直接挂载到 `window` 全局对象上。由于 `window` 对象在页面关闭前永远不会被回收，这些变量就会一直常驻内存。

**代码示例：**

JavaScript

```
function createLeak() {
  // 漏写了 let/const，导致 leakData 直接变成了 window.leakData
  leakData = new Array(10000).fill('我是泄露的数据'); 
  
  // 在普通函数中，this 默认指向 window
  this.moreLeakData = "更多泄露的数据"; 
}

createLeak();
```

**解决方案：**

在 JavaScript 文件或脚本的顶部添加 `"use strict";` 开启严格模式。这样在给未声明的变量赋值时，浏览器会直接报错，从而避免意外的全局变量。

### 2. 被遗忘的定时器或回调函数

当我们在代码中使用 `setInterval` 等定时器时，如果定时器的回调函数内部引用了外部的变量（形成闭包），那么只要这个定时器还在运行，这些外部变量就永远无法被垃圾回收机制释放。

**代码示例：**

JavaScript

```
function startTimer() {
  const serverData = { hugeArray: new Array(100000).fill('数据') }; 
  
  setInterval(() => {
    // 只要定时器不停止，serverData 所在的内存就永远不会被回收
    console.log('正在轮询数据...', serverData); 
  }, 1000);
}

startTimer();
```

**解决方案：**

在不需要定时器时（例如在 Vue/React 组件的销毁生命周期钩子中），务必使用 `clearInterval()` 或 `clearTimeout()` 将其手动清除。

### 3. 未清理的事件监听器

我们经常会给 `window`、`document` 或者某些特定的 DOM 元素绑定事件监听器。如果绑定的回调函数中引用了大量数据，且在页面跳转或组件销毁时忘记解绑这些事件，就会造成严重的内存泄漏。

**代码示例：**

JavaScript

```
function addListener() {
  const hugeObject = new Array(10000).fill('数据');
  
  function onResize() {
    console.log('窗口大小改变了，处理数据：', hugeObject);
  }
  
  // 给 window 绑定了事件，hugeObject 被闭包引用
  window.addEventListener('resize', onResize); 
  
  // 假设后来这个组件或功能被移除了，但忘记调用 removeEventListener
  // 那么 hugeObject 会随着 window 的 resize 事件一直存活在内存中
}

addListener();
```

**解决方案：**

养成良好的习惯，`addEventListener` 和 `removeEventListener` 必须成对出现。在组件卸载时，一定要移除对应的事件监听。

### 4. 闭包的滥用

闭包是 JavaScript 非常强大的特性，但如果不加控制地使用，特别是当一个长生命周期的闭包（例如挂载在 DOM 事件上）内部引用了一个非常大的局部变量时，这个大变量就无法在函数执行完毕后被销毁。

**代码示例：**

JavaScript

```
function assignHandler() {
  const element = document.getElementById('button');
  const largeData = new Array(10000).fill('庞大的局部变量'); 
  
  // 闭包产生：onclick 函数引用了外部的 largeData
  element.onclick = function() {
    // 只要 button 元素还在页面上，largeData 就不会被回收
    console.log(largeData); 
  };
}

assignHandler();
```

**解决方案：**

如果闭包中只需要用到大对象的一小部分属性，就提取那一小部分；或者在外部函数逻辑的最后，将大对象手动赋值为 `null` 以切断引用。

### 5. 脱离 DOM 的引用 (Detached DOM)

有时候我们需要用 JavaScript 动态删除页面上的 DOM 节点。但是，如果你在 JS 的变量或对象中依然保留着对这个 DOM 节点的引用，那么这个节点（及其所有的子节点）就虽然不在页面上显示了，却依然占据着 JS 的堆内存。

**代码示例：**

JavaScript

```
// 在 JS 对象中保留了对 DOM 节点的引用
let detachedNodes = {
  btn: document.getElementById('button')
};

function removeElement() {
  // 在 HTML 页面结构中移除了该元素
  document.body.removeChild(document.getElementById('button'));
  
  // 但是！detachedNodes 对象里依然有它的引用。
  // 此时这个 button 就变成了一个“游离态”的 DOM 节点，无法被垃圾回收。
}

removeElement();
```

**解决方案：**

在通过 DOM API 删除节点后，记得把对应的 JS 变量也清理掉：`detachedNodes.btn = null;`。

### 6. Map / Set 数据结构使用不当

在使用 `Map` 和 `Set` 时，它们对存储的对象默认是**强引用**。这意味着，如果你把一个对象作为 key 存入 `Map`，即使这个对象在程序的其他所有地方都不再使用了，由于 `Map` 还连着它，它就不会被垃圾回收。

**代码示例：**

JavaScript

```
let myMap = new Map();
let myNode = document.getElementById('someNode');

// 将 DOM 节点作为 key 存入 Map
myMap.set(myNode, '附加信息');

// 稍后我们从页面上删除了这个节点，并把引用置空
document.body.removeChild(myNode);
myNode = null; 

// 发生泄漏：因为 myMap 依然强引用着那个 DOM 节点，导致它无法被回收
```

**解决方案：**

在现代 JavaScript 开发中，如果需要建立“对象到数据”的映射关系，且不希望影响垃圾回收，应该优先使用 **`WeakMap`** 和 **`WeakSet`**。它们的键是弱引用的，一旦对象在外部没有其他强引用，垃圾回收器就会自动将其连同映射关系一起回收掉。
