**面试标准答句（JavaScript 继承机制 极简版）**

在面试中谈论继承，建议按照“核心痛点 -> 演进过程 -> 终极方案”的逻辑来回答，这样能体现你对 JS 继承发展史的宏观掌控。

你可以这样回答：

**1. 概念与痛点（为什么需要那么多继承方式）**

“在 JavaScript 中实现继承，核心是为了让子类能够重用父类的属性和方法，同时还能拥有自己独立的属性。由于 JS 是基于原型的，早期的继承方式（如**原型链继承**）存在一个致命缺陷：如果父类包含引用类型属性（如数组），所有子类实例会**共享**这块内存，修改一个实例就会导致相互篡改。”

**2. 继承方案的演进与权衡**

“为了解决共享问题，演进出了不同的方案，但各有优劣：

- **构造函数继承（借用 call）：** 在子类构造函数里调用父类 `Parent.call(this)`，解决了属性共享问题，但缺点是**无法继承父类原型链上的方法**。
    
- **组合继承：** 将前两种结合，既用 `call` 继承属性，又用 `Child.prototype = new Parent()` 继承方法。解决了前两者的缺点，但代价是**父类构造函数被执行了两次**，造成了额外的性能开销。”
    

**3. 终极方案：寄生组合式继承（核心得分点）**

“为了避免组合继承调用两次父类构造函数的开销，目前的最佳实践是**寄生组合式继承**。

它的核心思路是：通过借用 `call` 来继承父类实例的属性，同时通过 `Object.create(Parent.prototype)` 来浅拷贝父类的原型对象作为子类的原型，最后手动修复 `constructor` 指向。

这也是 ES6 中 `class extends` 语法糖底层经过 Babel 编译后实际采用的核心继承逻辑。”
