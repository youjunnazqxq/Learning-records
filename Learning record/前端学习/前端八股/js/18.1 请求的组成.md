从你前面关于 AJAX 和 Axios 的问题可以看出来，你正在一层层揭开网络请求的底层面纱。这是一个非常棒的学习路径！

不管是原生的 `XMLHttpRequest`、现代的 `fetch` 还是封装好的 `Axios`，它们最终向服务器发送的，都是一个符合 **HTTP 协议规范的网络请求报文**。

你可以把一个网络请求想象成寄一个快递。在底层，一个标准的 HTTP 请求主要由 **4 个部分**组成：

### 1. 请求行（Request Line）—— “快递单的核心信息”

这是请求的第一行，包含了三个最基础的信息：

- **请求方法（Method）**：决定了你对服务器要做什么。最常用的是 `GET`（我要取东西）和 `POST`（我要送东西）。除此之外还有 `PUT`（修改）、`DELETE`（删除）等。
    
- **请求地址（URL/URI）**：明确告诉网络你要访问哪个服务器的哪个接口（比如 `/api/getUser`）。如果你用的是 GET 请求，URL 后面通常还会跟着 `?name=张三` 这样的参数。
    
- **协议版本**：通常是 `HTTP/1.1` 或 `HTTP/2`，这部分通常由浏览器底层自动帮你填好。
    
- _【长什么样】：_ `POST /api/login HTTP/1.1`
    

### 2. 请求头（Request Headers）—— “包裹上的附加说明书”

紧跟在请求行下面，由一行行键值对（Key: Value）组成。它的作用是把客户端的运行环境、认证信息、以及包裹的数据格式等“元数据”告诉服务器。

常见的请求头有：

- **`Content-Type`**：极其重要！告诉服务器你发过去的请求体（Body）是什么格式的。比如 `application/json`（JSON格式）或者 `multipart/form-data`（上传文件用的格式）。
    
- **`Authorization`**：你的通行证/门票。通常存放用户登录后获取的 Token，证明你有权限请求这个接口。
    
- **`User-Agent`**：告诉服务器你是用什么浏览器、什么操作系统发起的请求（经常被用来做简单的反爬虫检查）。
    
- _【长什么样】：_ `Host: api.example.com`
    
    `Content-Type: application/json`
    

### 3. 空行（Blank Line）—— “分割线”

这是 HTTP 协议里非常严格的规定：在请求头和请求体之间，**必须且只能有一个空行**。

服务器在解析你的请求时，只要读到了这个空行，它就知道：“哦，附加的说明书（Headers）读完了，接下来的内容全都是真正的业务数据（Body）了”。

### 4. 请求体（Request Body / Payload）—— “快递盒里的真正物品”

这是你要发送给服务器的**实质性数据内容**。

- 如果你要提交一个包含账号密码的登录表单，或者上传一张头像，这些真实的数据就放在请求体里。
    
- **注意**：`GET` 请求通常是没有请求体的（因为它的数据都挂在 URL 上了）；而 `POST`、`PUT` 等请求通常都会携带请求体。
    
- _【长什么样】：_ `{"username": "admin", "password": "123"}`
