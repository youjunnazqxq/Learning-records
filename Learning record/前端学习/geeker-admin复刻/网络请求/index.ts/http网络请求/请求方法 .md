

### 1. GET：查 (Read)

**含义**：向服务器索取数据。

**场景**：

- 打开淘宝首页（获取商品列表）。
    
- 查看个人主页（获取用户信息）。
    
- 搜索关键词（获取搜索结果）。
    

**特点**：

- **它是“安全”的**：单纯的 GET 请求不应该修改服务器上的数据（只读）。
    
- **参数在 URL 里**：因为 GET 没有“请求体 (Body)”，所以参数通常拼接在 URL 后面。
    
    - 例如：`/api/user?id=1001`
        
- **会被缓存**：浏览器会自动缓存 GET 请求的结果。
    

> **Axios 写法：**
> 
> TypeScript
> 
> ```
> // 第二个参数是 config，参数放在 params 字段里
> http.get("/user/list", { params: { status: 1 } })
> ```

---

### 2. POST：增 (Create)

**含义**：向服务器提交数据，通常用于**创建**新资源。

**场景**：

- 注册新账号。
    
- 发布一条朋友圈。
    
- 上传一张图片。
    

**特点**：

- **参数在 Body 里**：数据被包裹在请求体中，不会显示在 URL 上，所以比 GET 安全一点点（但还是要加密）。
    
- **数据量无限制**：你想发多少数据都可以（取决于服务器设置），所以上传文件必须用 POST。
    

> **Axios 写法：**
> 
> TypeScript
> 
> ```
> // 第二个参数就是数据对象 (data)
> http.post("/user/login", { username: "admin", password: "123" })
> ```

---

### 3. PUT：改 (Update)

**含义**：向服务器传送数据，用来**更新**资源。

**场景**：

- 修改个人简介。
    
- 修改密码。
    
- 编辑已经发布的文章。
    

**特点**：

- **它是“覆盖式”更新**：通常语义上，PUT 意味着用你发送的新数据，**完全替换**掉旧数据。
    
- _(注：还有一个兄弟叫 `PATCH`，它是“局部更新”，比如只改一个头像，不改昵称。但在很多项目中，为了省事，后端往往统一用 PUT 或 POST 来处理更新逻辑。)_
    

> **Axios 写法：**
> 
> TypeScript
> 
> ```
> // 只有 ID 为 88 的用户才会被修改
> http.put("/user/update", { id: 88, nickname: "NewName" })
> ```

---

### 4. DELETE：删 (Delete)

**含义**：请求服务器**删除**指定的资源。

**场景**：

- 删除购物车里的商品。
    
- 注销账号。
    
- 删除评论。
    

**特点**：

- 通常只需要传一个 ID 过去即可。
    

> **Axios 写法：**
> 
> TypeScript
> 
> ```
> // 有时候参数在 URL 路径里，有时候在 params 里，看后端怎么定
> http.delete("/user/delete", { params: { id: 88 } })
> ```

### ⚖️ 经典面试题：GET 和 POST 的核心区别？

虽然它们本质上都是 TCP 链接，但在 HTTP 协议规范和实际使用中有巨大区别。我用一个 **“明信片 vs 快递包裹”** 的例子来比喻：

|**特性**|**GET (明信片)**|**POST (快递包裹)**|
|---|---|---|
|**数据位置**|**URL (地址栏)**<br><br>  <br><br>就把字写在明信片背面，路人都能看见。|**Body (请求体)**<br><br>  <br><br>东西装在箱子里封好，外面看不见。|
|**数据大小**|**有限制**<br><br>  <br><br>浏览器对 URL 长度有限制（一般几KB）。|**无限制**<br><br>  <br><br>箱子想多大就多大。|
|**用途**|**获取数据 (Read)**|**提交/修改数据 (Write)**|
|**安全性**|❌ 差（参数留在浏览器历史记录里）|✅ 较好（不会留在历史记录里）|
|**缓存**|✅ 浏览器会主动缓存|❌ 默认不缓存|

### 5. 特殊嘉宾：OPTIONS 方法

在你开发过程中，你可能会在 Network 里看到一个叫 `OPTIONS` 的请求，但你明明没写这个代码。

**别慌，这是浏览器的“自动安检机制”。**

- **场景**：当你跨域（CORS）发送复杂请求（比如加了自定义 Header `x-access-token`，或者用 PUT/DELETE 方法）时。
    
- **动作**：浏览器会**自动**先发一个 `OPTIONS` 请求去问服务器：“你好，我接下来想发一个带 Token 的 PUT 请求，你允许吗？”
    
- **结果**：
    
    - 如果服务器说“允许”，浏览器才会真正发送你的 PUT 请求。
        
    - 如果服务器说“不允许”，你的请求就会直接报错（CORS Error）。
        

这就是传说中的 **“预检请求 (Pre-flight request)”**。

### 总结

对于你的 Geeker-Admin 项目封装：

1. **GET**: 用来拿列表、查详情。
    
2. **POST**: 用来登录、新增用户。
    
3. **PUT**: 用来编辑用户。
    
4. **DELETE**: 用来删除用户。
