

### 1. 第一大金刚：`Content-Type` (内容类型)

**这是最容易报错、最容易导致前后端扯皮的地方。**

它的作用是告诉服务器：“**我这个包裹里装的，到底是什么格式的数据？**”

如果你传了 JSON 数据，却贴了个“我是图片”的标签，服务器解析不出来，就会直接报错。

#### 常见的三种类型：

- **A. `application/json` (最常用)**
    
    - **含义**：告诉服务器，我发给你的是 **JSON 字符串**。
        
    - **样子**：`{"name": "geeker", "age": 18}`
        
    - **场景**：现在的现代 Web 开发（Vue, React）配合 RESTful API，**99% 的情况都用这个**。
        
    - **Axios 表现**：当你传一个普通对象给 `data` 时，Axios **默认**就会帮你加上这个头。所以你平时不用手写。
        
- **B. `application/x-www-form-urlencoded` (老式表单)**
    
    - **含义**：这是传统 `<form>` 表单提交的格式。
        
    - **样子**：`name=geeker&age=18` (类似 URL 里的参数串)
        
    - **场景**：一些比较旧的后端接口，或者登录接口有时候会要求用这个格式。
        
    - **注意**：如果你用这个，你需要用 `qs.stringify(data)` 把对象转一下码。
        
- **C. `multipart/form-data` (文件上传)**
    
    - **含义**：**专门用来传文件的**。它可以把文件数据和文本数据混合在一起发过去。
        
    - **场景**：上传头像、上传Excel。
        
    - **Axios 表现**：当你构建一个 `FormData` 对象并发给 axios 时，axios 会自动识别并加上这个头。

### 2. 第二大金刚：`Authorization` (身份认证)

**这就是你的 VIP 卡 / 门禁卡。**

它的作用是告诉服务器：“**我是谁，我有没有权限进这个门。**”

#### 两种常见的写法：

- **A. 标准写法：Bearer Token**
    
    - 这是国际通用的标准。
        
    - **格式**：`Authorization: Bearer <token字符串>`
        
    - (注意中间有个空格，`Bearer` 意思是“持有者”)
        
- **B. 自定义写法 (你的项目在用的)**
    
    - 很多公司喜欢自己定规则，不走标准。
        
    - **格式**：`x-access-token: <token字符串>`
        
    - **格式**：`Token: <token字符串>`
        
    - **说明**：你代码里的 `config.headers.set("x-access-token", ...)` 就是在做这件事。只要前后端商量好名字（Key），用什么都行。
        

---

### 3. 第三大金刚：`Accept` (我想要什么)

**这是“点菜”用的。**

- `Content-Type` 是告诉服务器“**我发给你**的是什么”。
    
- `Accept` 是告诉服务器“**我希望你返回给我**的是什么”。
    

通常默认都是 `application/json`。意思是：“请把结果打包成 JSON 发给我，别发 XML 或者 HTML 给我，我看不懂。”

---

### 🧐 为什么你平时写代码感觉不到它们？

你可能会问：“既然它们这么重要，为什么我刚才的代码里只写了 Token，没写 Content-Type 呢？”

**因为 Axios 这个库太聪明了。**

它有一个**“自动推断机制”**：

1. **看数据类型**：如果你 `post` 的数据是一个普通的 JavaScript 对象 `{ a: 1 }`，Axios 会自动把 `Content-Type` 设为 JSON。
    
2. **看对象类型**：如果你 `post` 的是一个 `FormData` 对象（文件流），Axios 会自动设为 `multipart/form-data`。
    

**你需要手动干预的时候：**

只有当后端比较“奇葩”，比如后端说：“我虽然收的是 JSON，但我强制要求你头里必须写 `application/custom-thing`”，这时候你才需要去拦截器里手动 `config.headers.set(...)`。

### 总结

关于请求头，记住这两个最核心的就够了：

1. **Content-Type**: 包裹里的**数据格式**（JSON / 表单 / 文件）。
    
2. **Authorization (或 x-access-token)**: 你的**登录凭证**。
