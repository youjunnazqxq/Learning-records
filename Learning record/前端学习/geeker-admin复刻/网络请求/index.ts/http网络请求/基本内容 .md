
### 1. 起始行 (Request Line) —— 信封正面的“核心指令”

这是第一行，它最重要，直接告诉服务器：**我要做什么，以及找谁做。**

它包含三个关键信息：

- **方法 (Method)**：你想要干啥？
    
    - `GET`：**“给我看看”**（比如：打开网页、获取列表）。通常手里不拿东西（没有 Body）。
        
    - `POST`：**“给你这个”**（比如：登录提交密码、上传文件）。手里拿着数据给服务器。
        
    - `DELETE`：**“删掉它”**。
        
    - `PUT`：**“修改它”**。
        
- **地址 (URL)**：你去哪？（比如 `/user/login` 或 `/home`）。
    
- **协议版本**：我们用的是什么语言标准（通常是 `HTTP/1.1` 或 `HTTP/2`）。
    

> **例子：** `POST /login HTTP/1.1`
> 
> **翻译：** “我要用 POST 方法（提交数据），目标是 `/login` 接口，用的是 HTTP 1.1 标准。”

---

### 2. 请求头 (Headers) —— 信封上的“备注标签”

这就是我们刚才一直在折腾的地方！它是写给服务器的**附加信息**。

它是一行一行的 `Key: Value` 格式。

- **`Host`**：我去哪个主机（域名）。
    
- **`Content-Type`**：我包裹里装的是什么格式的数据？（是 JSON 文本，还是图片，还是表单？）。
    
- **`Authorization` / `x-access-token`**：**我有特权吗？我是谁？**（刚才代码里写的 Token 就在这里）。
    
- **`User-Agent`**：我是用什么浏览器访问的？
    

> **作用：** 服务器还没拆信，光看这些标签，就知道这封信是不是垃圾邮件，有没有权限拆开，以及该用什么工具拆。

---

### 3. 空行 (Empty Line) —— 物理分隔符

这听起来很滑稽，但它必不可少。

在“请求头”和“请求体”之间，**必须**有一行完全空白的内容。

- 它的作用就是告诉服务器：“好了，上面的备注标签写完了，接下来是正文内容了！”
    

---

### 4. 请求体 (Body) —— 信封里的“信纸/货物”

这是你真正想要传输的具体**数据**。

- **如果是 GET 请求**：通常这里是**空的**（因为 GET 只是去要把东西，自己不用带干粮）。
    
- **如果是 POST 请求**：这里面装的就是数据。
    
    - 比如登录时，这里装的就是：`{ "username": "admin", "password": "123" }`。
        

---

### 📝 总结：一眼看懂“裸体”的请求

如果扒掉 Axios 的外衣，一个真实的 HTTP 请求文本长这样：

HTTP

```
POST /login HTTP/1.1           <-- 1. 起始行 (方法 + 地址)
Host: www.geeker.com           <-- 2. 请求头 (Headers) 开始
Content-Type: application/json <--    告诉后端：下面是 JSON 数据
x-access-token: vip-8888       <--    刚才写的 Token 就在这！
User-Agent: Chrome/90.0        <--    请求头结束

{"name": "admin", "pw": "123"} <-- 4. 请求体 (Body，隔了一个空行)
```

**现在回到你的代码：**

- **请求拦截器**就是帮你自动写 **第 2 部分 (Headers)** 的。
    
- **你在页面调 API 传的参数**，就是自动填入 **第 4 部分 (Body)** 的。
    

这样拆解下来，是不是觉得整个流程特别清晰了？
