
### 🗺️ 数据的“通关”之旅

当服务器给你的前端发回响应时，数据会经历以下严酷的“安检流程”：

#### 1. 第一关：收尾工作 (Cleanup)

- **动作**：不管请求成功还是失败，拦截器首先会做两件事：
    
    - 🗑️ **移除 Pending**：告诉取消器“这个请求完事了，从列表中删掉”。
        
    - 🛑 **关闭 Loading**：如果开启了全屏动画，立刻关掉，不能让用户干等。
        

#### 2. 第二关：身份核查 (Security Check)

- **检查对象**：`data.code`
    
- **场景**：如果 `code === 401` (ResultEnum.OVERDUE)。
    
- **动作**：
    
    - 👉 **清空 Token** (Pinia)。
        
    - 👉 **踢回登录页** (Router replace)。
        
    - 👉 **报错阻断** (Reject)。
        
- **意义**：保护系统安全，防止非法或过期的用户停留。
    

#### 3. 第三关：业务质检 (Business Check)

- **检查对象**：`data.code`
    
- **场景**：如果 `code !== 200` (ResultEnum.SUCCESS)。
    
- **动作**：
    
    - 📢 **全局弹窗**：直接把后端返回的 `msg` 弹出来（如“密码错误”）。
        
    - 🚫 **阻断流程**：`Promise.reject(data)`，让组件里的代码停止执行。
        
- **意义**：统一处理业务逻辑错误，页面组件只需要关心“成功”的情况。
    

#### 4. 第四关：灾难救援 (Disaster Recovery)

- **触发条件**：进入了 `error` 回调（HTTP 状态码非 200，或断网/超时）。
    
- **动作**：
    
    - ⏳ **超时检测**：包含 "timeout" -> 报“请求超时”。
        
    - 🔌 **断网检测**：包含 "Network Error" -> 报“网络异常”。
        
    - 📝 **状态码翻译**：有 `response.status` -> 调 `checkStatus` (404/500/503...)。
        
    - 🚑 **离线跳转**：`navigator.onLine` 为 false -> 强跳 `/500` 页面。
        

#### 5. 最终放行 (The Happy Path) ✅

- **触发条件**：HTTP 200 且 业务代码 200。
    
- **动作**：剥去 Axios 的 `status/headers` 外壳，**只返回 `data`**。
    
- **结果**：你的 Vue 组件里拿到的直接就是 `{ code, msg, data }`，干净利落。

### 🌟 你现在的 Axios 拥有了哪些“超能力”？

|**能力**|**以前 (原生 Axios)**|**现在 (封装后)**|
|---|---|---|
|**返回值**|复杂的 `res.data.data`|干净的 `res.data`|
|**Loading**|每个页面手动开关|**全自动** (可配置关闭)|
|**重复请求**|狂点按钮发多次|**自动防抖** (保留最后一次)|
|**报错提示**|每个页面 `try-catch` 弹窗|**全局自动弹窗**|
|**Token失效**|需要手动判断跳转|**自动登出 + 跳转**|
|**断网/超时**|页面可能卡死无反应|**自动识别 + 友好提示**|

### 👨‍💻 下一步建议

现在 `src/api/index.ts` 及其附属文件（`checkStatus.ts`, `ResultEnum.ts`）已经非常完美了。

接下来的开发流程通常是：

1. **去 `src/api/modules/` 文件夹**：
    
    - 创建业务接口文件，比如 `user.ts`, `order.ts`。
        
    - 在这里引入你封装好的 `http` 实例。
        
    - 定义具体的 API 方法（如 `login`, `getUserList`）。
        
2. **去 `.vue` 组件**：
    
    - 调用这些 API 方法。
        
    - 享受丝滑的 `await` 调用，无需处理那些烦人的报错逻辑。
        

**这套封装是很多中大型企业项目的标准配置，恭喜你掌握了它！** 🚀
