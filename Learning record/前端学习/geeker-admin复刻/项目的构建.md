复刻 **Geeker-Admin** 这样的企业级项目，从零创建的过程不仅仅是敲几行代码，而是一套标准的**工程化落地流程**。

根据我们刚才的实操，一个规范的前端项目创建过程可以总结为以下五个阶段：

---

### 1. 环境准备与项目初始化

这是项目的“奠基”阶段，确定技术基调。

- **确定目录**：选择一个不含中文和空格的代码存放路径。
    
- **脚手架初始化**：使用 `npm create vite@latest` 等工具生成代码模板。
    
- **技术栈选型**：明确框架（Vue3）、编程语言（TypeScript）及构建工具（Vite）。
    
- **处理规范**：如遇到目录非空或命名报错，需遵循 npm 规范（全小写、无特殊字符）。
    

### 2. 依赖安装与启动测试

有了“图纸”后，需要把实际的工具包下载回来。

- **安装依赖**：执行 `npm install` 下载 `node_modules`。
    
- **验证环境**：运行 `npm run dev` 确保基础模板能正常在浏览器打开。
    
- **清理冗余**：删除脚手架自带的 `HelloWorld.vue` 等无用示例文件，为复刻腾出空间。
    

### 3. Git 版本管理建立

这是为了给你的复刻过程提供“后悔药”和“存档点”。

- **仓库初始化**：执行 `git init` 开启版本控制。
    
- **配置忽略文件**：设置 `.gitignore`，防止 `node_modules` 等体积巨大的冗余文件进入仓库。
    
- **首次提交**：通过 `git add .` 和 `git commit` 保存最初的干净状态。
    

### 4. 项目结构与工程化配置

仿照 Geeker-Admin 的目录结构，为后续开发打好地基。

- **目录规范化**：手动创建 `api`、`views`、`stores`、`components` 等核心文件夹。
    
- **路径别名**：在 `vite.config.ts` 和 `tsconfig.json` 中配置 `@` 路径映射。
    
- **环境变量**：创建 `.env.development` 等文件，配置不同环境下的 API 地址。
    

### 5. 核心基建封装（你的下一个目标）

进入真正的代码编写阶段。

- **网络请求封装**：基于 Axios 封装统一的请求拦截、响应处理和错误提示。
    
- **状态管理**：配置 Pinia 并处理数据持久化。
    
- **路由架构**：搭建基础布局（Layout）和动态菜单权限逻辑。
    

---

**恭喜你！现在你的项目已经处于第 3 和第 4 阶段之间。**

**接下来你想继续哪一步？**

- **选项 A**：配置 `.gitignore` 并进行你的第一次 Git 正式提交。
    
- **选项 B**：在项目中手动建立 Geeker-Admin 那样规范的目录文件夹（`api`, `views` 等）。
    
- **选项 C**：去 `vite.config.ts` 配置 `@` 别名，解决以后写代码找不到路径的问题。
