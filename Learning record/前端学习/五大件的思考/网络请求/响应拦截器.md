

### 1. 剥离无用外壳 (数据解包)

Axios 默认非常“热心”，它会把后端返回的数据包装在一个大对象里，包含 `status` (HTTP状态码)、`headers` (响应头)、`config` (请求配置) 等等。但实际上，你的业务组件里往往只关心真正的业务数据（通常在 `response.data` 里）。

在拦截器里，我们直接 `return response.data`，帮组件把外包装拆掉。

### 2. 关闭全局 Loading 状态

有始有终。在请求拦截器里开启的 Loading 动画，必须在响应拦截器里关闭。无论是请求成功还是失败，都得把 Loading 关掉，否则页面就一直卡着转圈圈了。

### 3. 全局业务错误提示 (避免写一万个 `if...else`)

**这是新手最容易迷惑的地方：HTTP 状态码正常（200），不代表业务正常。**

很多后端会这么设计：不管密码对不对，HTTP 状态码统统返回 200，但会在返回的 JSON 里加一个 `code` 字段（比如 `code: 200` 才是成功，`code: 500` 是密码错误）。

如果不做拦截，你每个页面都要写一遍 `if (res.code !== 200) { 提示错误 }`。在响应拦截器里统一判断，如果业务报错，直接弹出全局提示框（如 `ElMessage.error`），并阻断流程。

### 4. 统一处理 Token 失效 (401 拦截)

这是最经典的场景。如果后端发现你的 Token 过期了，通常会返回 401 状态码（或特定的业务 code）。拦截器一旦抓到 401，就会直接执行两步：

1. 清除本地存的废弃 Token。
    
2. 强制把用户踢回 `/login` 登录页。
    

---

### 💻 典型的响应拦截器代码模板

结合上面的逻辑，接着我们之前的 `request` 实例，完整的响应拦截器通常这样写：

JavaScript

```
// 假设你使用 Element Plus 进行全局提示
import { ElMessage } from 'element-plus'; 

// 添加响应拦截器
request.interceptors.response.use(
  (response) => {
    // --------------------------------------------------
    // 1. 关闭全局 Loading (假设 loadingInstance 在外部定义)
    // --------------------------------------------------
    if (loadingInstance) loadingInstance.close();

    // --------------------------------------------------
    // 2. 数据解包：直接拿到后端真正返回的 JSON
    // --------------------------------------------------
    const res = response.data;

    // --------------------------------------------------
    // 3. 业务状态码拦截 (这里假设后端约定 code 为 200 时是完全成功)
    // --------------------------------------------------
    if (res.code && res.code !== 200) {
      // 弹出后端的错误提示信息
      ElMessage.error(res.message || '服务器开小差了');

      // 4. 单独处理 Token 失效的业务逻辑 (假设后端约定 401 代表未登录)
      if (res.code === 401) {
        localStorage.removeItem('user_token');
        window.location.href = '/login'; // 强制跳回登录页
      }

      // 抛出错误，阻断流程，让组件里的代码走到 catch() 里去，而不是 then()
      return Promise.reject(new Error(res.message || 'Error'));
    }

    // 如果一切正常，直接把干净的数据给组件
    return res;
  },

  (error) => {
    // --------------------------------------------------
    // 5. 处理 HTTP 网络层面的硬报错 (如 404, 500，或断网)
    // --------------------------------------------------
    if (loadingInstance) loadingInstance.close();

    let message = '';
    if (error && error.response) {
      // 根据 HTTP 状态码匹配对应的错误提示
      switch (error.response.status) {
        case 400: message = '请求参数错误'; break;
        case 401: 
          message = '登录状态已过期，请重新登录'; 
          localStorage.removeItem('user_token');
          window.location.href = '/login';
          break;
        case 403: message = '您没有权限访问该接口'; break;
        case 404: message = '请求的接口不存在 (404)'; break;
        case 500: message = '服务器内部崩溃 (500)'; break;
        default: message = `网络异常 (${error.response.status})`;
      }
    } else {
      // 如果 error.response 不存在，通常是请求超时或本地断网了
      message = '网络连接失败，请检查您的网络';
    }

    ElMessage.error(message);
    return Promise.reject(error);
  }
);
```

有了请求拦截器和响应拦截器这一对“门神”，你的业务代码在调用 API 时就会感到无比的轻松。你不需要管报错提示，不需要管解包，拿到数据直接用就行了。
