

理解这 5 个阶段，你就能完全明白为什么前端项目中要专门建立一个单独的 `api` 或 `utils/request` 目录来进行封装了。

一次最基本的 Axios 请求动作包含以下全生命周期：

### 1. 构造与发起请求 (Request Initiation)

这是起点。在这个阶段，前端代码需要明确诉求，也就是组合出我们在第一个问题中提到的**配置对象 (Config)**。

- **你要去哪？** 确定 `url` (接口地址) 和 `baseURL`。
    
- **你要干什么？** 确定 `method` (GET 获取、POST 提交、PUT 更新、DELETE 删除等)。
    
- **你带了什么？** 确定传参 (`params` 或 `data`)。
    

### 2. 请求拦截器介入 (Request Interceptor)

这是 Axios 最强大的特性之一。请求发出之前，会**强制先经过请求拦截器**。这就像上飞机前的安检。

- **统一携带凭证：** 在这里统一从本地存储 (localStorage/Vuex/Pinia) 中取出 Token，硬塞到请求头 (`Headers.Authorization`) 里。
    
- **全局状态控制：** 开启页面的全局 Loading 动画，告诉用户“数据正在加载中”。
    
- **数据安全处理：** 对即将发送的数据进行加密，或者对空字符串进行过滤清洗。
    

### 3. 网络传输与服务器处理 (Network & Server Processing)

请求正式离开前端，通过 HTTP/HTTPS 协议飞向后端。

- 后端接收参数、校验权限、查询数据库、执行业务逻辑。
    
- 后端将处理结果打包成 JSON 格式，并附带 HTTP 状态码（如 200 成功，401 未授权，500 服务器错误），顺着网线原路返回。
    
- _(注意：这一步是后端的黑盒，前端只能被动等待，所以可以通过设置 `timeout` 来防止无限等待。)_
    

### 4. 响应拦截器介入 (Response Interceptor)

数据回到前端的第一站，不是直接进入你的业务代码，而是**先经过响应拦截器**。这就像海关的入境检查。

- **剥离外层包装：** Axios 默认会把后端返回的数据包在一个 `data` 属性里。通常我们会在拦截器里直接 `return response.data`，帮业务层剥去这层无用的外壳。
    
- **统一错误处理：** 如果 HTTP 状态码是 401（Token 过期），拦截器可以直接触发强制登出逻辑并跳转登录页；如果是 500，直接弹窗提示“服务器异常”。
    
- **关闭状态：** 关闭第 2 步中开启的全局 Loading 动画。
    

### 5. 业务逻辑处理 (Business Logic)

经历过拦截器的清洗和过滤，**干净且正确**的数据才会最终来到你的组件或页面中（也就是你写的 `.then()` 或 `await` 下面的代码）。

- **渲染页面：** 将拿到的数据赋值给 Vue 的 `ref` 或 React 的 `state`，页面更新。
    
- **兜底报错：** 如果在前面的步骤中发生了拦截器无法解决的特殊业务错误，进入 `.catch()` 并在 UI 上提示用户。
    

---

总结来说，一个基本请求就是：**配置 -> 安检（请求拦截） -> 传输 -> 进关（响应拦截） -> 渲染**。

我们项目中之所以要封装 Axios，核心目的就是**把第 2 步（请求拦截）和第 4 步（响应拦截）的通用逻辑集中在一起处理，避免在每个页面的第 1 步和第 5 步写重复的废话。**

你觉得我们下一步是先写一段**请求拦截器**的代码（比如怎么注入 Token），还是先看看**响应拦截器**的代码（比如怎么做全局错误提示）？
