

### 1. 协议 (Protocol)

- **内容：** `https://`
    
- **作用：** 规定了浏览器和服务器之间通讯的“语言规则”。在网络请求中最常见的就是 `http://`（明文传输）和 `https://`（加密传输）。
    

### 2. 域名/主机名 (Hostname / Domain)

- **内容：** `www.example.com` （也可以是一串 IP 地址，比如 `192.168.1.100`）
    
- **作用：** 指明了服务器在互联网上的具体“门牌号”。网络请求的第一步就是通过域名找到对应的服务器。
    

### 3. 端口号 (Port)

- **内容：** `:8080`
    
- **作用：** 一台服务器上可能会运行很多个不同的程序，端口号就是进入特定程序的“入口编号”。
    
- _注意：如果网址里没写端口号，HTTP 默认是 80，HTTPS 默认是 443。在本地开发前端项目时，经常会看到诸如 `localhost:5173` 或 `localhost:8080` 的地址。_
    

### 4. 路径 (Path)

- **内容：** `/api/v1/user/list`
    
- **作用：** 标明你要访问这台服务器上的哪个具体资源或接口。这就是后端程序员在编写后台代码时定义的路由路径。
    

### 5. 查询参数 (Query Parameters)

- **内容：** `?status=active&page=1`
    
- **作用：** 附加给服务器的额外信息。以 `?` 开头，多组数据之间用 `&` 连接，格式是 `键=值`。这通常用于 GET 请求中的数据过滤、分页、搜索等。
    

### 6. 哈希/片段标识符 (Hash / Fragment)

- **内容：** `#top`
    
- **作用：** 仅仅是给**前端浏览器**看的，用于页面内的锚点定位（比如跳到网页顶部）或前端路由（如 Vue/React 的 Hash 路由模式）。**这部分内容压根就不会发送给后端服务器。**
    

---

### 网址结构与 Axios 的完美映射

理解了上面这些，你就能彻底明白为什么我们在封装 Axios 时要写对应的那些配置项了：

- **`baseURL` (基础路径)：** 通常对应前三部分 `协议 + 域名 + 端口`（例如：`https://www.example.com:8080`）。我们在项目中初始化 Axios 实例时全局配置一次，以后就不用每次都写前缀了。
    
- **`url` (请求路径)：** 通常对应第 4 部分的 `路径`（例如：`/api/v1/user/list`）。我们每次写具体的 API 函数时传入。Axios 发送请求时，会自动把 `baseURL` 和 `url` 拼接起来。
    
- **`params` (查询参数对象)：** 对应第 5 部分。我们不需要手动去拼接恶心的 `?` 和 `&`，只要在 Axios 里传一个 JavaScript 对象 `{ status: 'active', page: 1 }`，Axios 会自动把它转换成 URL 参数拼在网址最后面。
