

### 第一副面孔：不加 `g` （像个侦探，挖得很深）

如果你的正则里没有 `g`，`match()` 找到**第一个**符合条件的字符串就会立刻停下来。但是，它不仅会把找到的字符串给你，还会顺便给你一堆“详细的背景调查报告”。

**这通常用于：精准提取某一个复杂文本中的特定部分（借助括号分组）。**

JavaScript

```
// 假设我们有一段文本，我们想提取里面的日期
const str = "今天的日期是 2026-04-12，明天是 2026-04-13。";

// 正则：(\d{4})代表4位数字年份，(\d{2})代表2位月份和日期。括号代表“提取分组”
const reg = /(\d{4})-(\d{2})-(\d{2})/; 

const result = str.match(reg);
console.log(result);
```

**此时 `result` 打印出来是一个非常特殊的数组：**

JavaScript

```
[
  "2026-04-12",  // [0]: 完整匹配到的字符串
  "2026",        // [1]: 第一个括号 () 提取的内容（年份）
  "04",          // [2]: 第二个括号 () 提取的内容（月份）
  "12",          // [3]: 第三个括号 () 提取的内容（日期）
  index: 7,      // 匹配到的字符串在原文本中是从哪个位置开始的
  input: "今天的日期是 2026-04-12，明天是 2026-04-13。", // 原文本是什么
  groups: undefined // 命名分组（进阶用法，暂不展开）
]
```

你看，虽然文本里有两个日期，但它只管第一个。并且，因为你用了括号 `()`，它把年、月、日非常贴心地帮你单独拆解出来了（分别在数组的索引 1、2、3 里面）。

### 第二副面孔：加了 `g` （像个收割机，只看表面）

如果你的正则末尾加了 `g`（全局匹配），`match()` 的性格就变了。它会在整个文本里从头扫到尾，把**所有**符合条件的字符串全找出来。但是，**它不再提供任何详细信息，也不管你有没有写括号分组**。

**这通常用于：统计数量，或者提取所有的目标词汇。**

JavaScript

```
const str = "今天的日期是 2026-04-12，明天是 2026-04-13。";

// 注意末尾加了 g
const reg = /(\d{4})-(\d{2})-(\d{2})/g; 

const result = str.match(reg);
console.log(result);
```

**此时 `result` 打印出来是一个非常干净、纯粹的数组：**

JavaScript

```
[
  "2026-04-12",
  "2026-04-13"
]
```

你看，它找到了两个日期，但是之前那种拆解出的 `2026`、`04`，以及 `index` 位置信息，**全都没了**。

---

### ⚠️ 最致命的坑：找不到的时候

无论有没有 `g`，只要 `match()` 在字符串里**什么都没找到**，它都会**返回 `null`**（而不是空数组 `[]`）。

这会导致前端经常出现一个经典报错：`Cannot read properties of null`。

所以，在企业级开发中，调用 `match()` 之后，**永远要先做一步判空操作**：

JavaScript

```
const result = str.match(reg);

// 防呆设计：先判断 result 不是 null，再去拿里面的数据
if (result) {
  console.log(result[0]); 
} else {
  console.log("没找到想要的数据");
}
```
