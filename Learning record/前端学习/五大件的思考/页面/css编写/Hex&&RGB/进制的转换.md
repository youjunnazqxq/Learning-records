要彻底弄懂这个转换规则，我们需要先破除对“十六进制”的恐惧感。

其实，**十六进制（Hex）和 RGB 只是同一种颜色的两种不同“方言”**。

- **RGB**：是我们人类习惯的**十进制**（逢十进一），包含红 (R)、绿 (G)、蓝 (B) 三个通道，每个通道的取值范围是 `0` 到 `255`。
    
- **Hex**：是计算机喜欢的**十六进制**（逢十六进一），使用 `0-9` 和字母 `a-f`（代表 10-15）来表示数字。
    

一个标准的 6 位 Hex 颜色代码（比如 `#409eff`），其实就是把 RGB 的三个数字，翻译成十六进制后，**像糖葫芦一样串在了一起**。

- 前两位 `40` 代表红色 (R)
    
- 中间两位 `9e` 代表绿色 (G)
    
- 后两位 `ff` 代表蓝色 (B)
    

我们以 Element Plus 的主色调 `#409eff`（对应 RGB 为 `64, 158, 255`）为例，拆解一下转换的具体数学规则：

### 1. Hex 转 RGB (十六进制 -> 十进制)

规则：**将每两位 Hex 字符拆开，第一位乘以 16，加上第二位乘以 1。**

_(注意：a=10, b=11, c=12, d=13, e=14, f=15)_

- **拆解红色段 `40`**：
    
    - $4 \times 16 + 0 \times 1 = 64 + 0 = \mathbf{64}$
        
- **拆解绿色段 `9e`**：
    
    - $9 \times 16 + e(14) \times 1 = 144 + 14 = \mathbf{158}$
        
- **拆解蓝色段 `ff`**：
    
    - $f(15) \times 16 + f(15) \times 1 = 240 + 15 = \mathbf{255}$
        

所以，`#409eff` 就完美转换成了 `rgb(64, 158, 255)`。这也就是你代码中 `parseInt(hexs[i], 16)` 这一行在底层做的事情。

---

### 2. RGB 转 Hex (十进制 -> 十六进制)

规则：**将 0-255 的数字除以 16，商作为第一位字符，余数作为第二位字符。如果算出来只有一位，前面要补 `0`。**

- **转换红色 `64`**：
    
    - $64 \div 16 = \mathbf{4}$，余数是 $\mathbf{0}$ $\rightarrow$ 拼起来是 `40`
        
- **转换绿色 `158`**：
    
    - $158 \div 16 = \mathbf{9}$，余数是 $\mathbf{14}$（对应十六进制的 $\mathbf{e}$） $\rightarrow$ 拼起来是 `9e`
        
- **转换蓝色 `255`**：
    
    - $255 \div 16 = \mathbf{15}$（对应 $\mathbf{f}$），余数是 $\mathbf{15}$（对应 $\mathbf{f}$） $\rightarrow$ 拼起来是 `ff`
        

最后把它们连起来加上 `#`，就变回了 `#409eff`。你代码里的 `toString(16)` 就是在做这个除法取余的运算，而 `if (hexs[i].length == 1) hexs[i] = "0" + hexs[i]` 就是那个“不够两位补零”的关键规则。
