

### 一、 核心定位与作用

- **作用：** 专门用于**“直系父子组件”**之间的数据传递。父组件像传递 HTML 属性一样把数据传下来，子组件用 `defineProps` 接收。
    
- **本质：** 它是 Vue 3 `<script setup>` 提供的一个**编译器宏**。这意味着你不需要 `import` 导入它，直接写在代码里，Vue 在编译时会自动识别并处理。
    

### 二、 核心铁律：单向数据流

- **绝对只读：** 子组件接收到的 Props 数据是**只读的**。你绝对不能在子组件内部直接去修改它（比如 `props.count = 2` 会报错）。
    
- **谁的数据谁做主：** 如果子组件想要改变这个数据，必须去通知数据的拥有者（父组件）来进行修改。这保证了复杂项目中数据流向的清晰可溯源。
    

### 三、 声明方式与语法

在子组件中，主要有两种声明接收的方式：

1. **数组简写版（适合极其简单的场景）：**
    
    JavaScript
    
    ```
    const props = defineProps(['title', 'count'])
    ```
    
2. **对象校验版（🌟 强烈推荐，适合项目开发）：**
    
    不仅能接收数据，还能限制类型、设置默认值和是否必填，让代码极其健壮。
    
    JavaScript
    
    ```
    const props = defineProps({
      title: {
        type: String,
        required: true // 必须传
      },
      count: {
        type: Number,
        default: 0 // 如果不传，默认是 0
      }
    })
    ```
    

### 四、 响应式与解构（避坑指南）

这也是我们刚才讨论的重点，Vue 的发展经历了一个演进过程：

- **过去（Vue 3.4 及以前）：** 直接写 `const { count } = props` 会**丢失响应式**。必须借助 `toRefs(props)` 包装一下，或者老老实实写 `props.count`。
    
- **现在（Vue 3.5 及以后）：** Vue 实现了**响应式 Props 解构**。你可以直接大胆地使用原生 JavaScript 解构 `const { count = 0 } = defineProps(...)`，并且在 `<script setup>` 中直接使用 `count`，底层会自动帮你保持响应式同步！
