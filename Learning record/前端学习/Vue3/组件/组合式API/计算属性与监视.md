
# Vue 3: Computed (计算属性) 核心速查

## 1. 核心定义 (Mental Model)

* **本质**：它是一个 **“派生状态” (Derived State)**。
* **逻辑**：`Output = Function(Input)`。
* **特性**：**自动追踪依赖** + **缓存机制**。只有当它依赖的响应式数据发生变化时，它才会重新计算；否则直接返回缓存值。
* **CS 类比**：
    * Excel 表格中的公式。
    * 数据库中的 **视图 (View)**。

---

## 2. 基础用法 (Read-Only)

这是最常见的场景，接收一个 getter 函数，返回一个 **只读的 ref 对象**。

```vue
<script setup>
import { ref, computed } from 'vue'

const price = ref(100)
const discount = ref(0.8)

// 1. 定义：依赖 price 和 discount
// 这是一个 ref 对象，JS 中需要 .value 访问
const finalPrice = computed(() => {
  return price.value * discount.value
})

const checkPrice = () => {
  console.log(finalPrice.value) // 80
  // finalPrice.value = 90 ❌ 报错：只读属性
}
</script>

<template>
  <div>原价: {{ price }}</div>
  <div>折后: {{ finalPrice }}</div>
</template>

3. 进阶用法 (Writable)
如果你需要对计算属性进行“赋值”操作（常见于 v-model 绑定），需要写成对象形式（包含 get 和 set）。
<script setup>
import { ref, computed } from 'vue'

const firstName = ref('John')
const lastName = ref('Doe')

// 定义可写的计算属性
const fullName = computed({
  // 读取时触发
  get() {
    return firstName.value + ' ' + lastName.value
  },
  // 写入时触发 (val 是新赋的值)
  set(val) {
    // 逻辑：拆分字符串，反向更新源数据
    const [first, last] = val.split(' ')
    firstName.value = first
    lastName.value = last
  }
})

// fullNam.value = 'Alice Smith' -> 会自动更新 firstName 和 lastName
</script>

<template>
  <input v-model="fullName" />
</template>

4. 核心面试/考点：Computed vs Methods
为什么不用普通函数代替？因为 性能。
| 特性 | Computed (计算属性) | Methods (普通方法) |
|---|---|---|
| 缓存机制 | ✅ 有缓存 | ❌ 无缓存 |
| 执行时机 | 仅当依赖变化时重新计算 | 每次组件渲染时都会执行 |
| 调用方式 | 像变量一样引用 (无括号) | 必须调用函数 (带括号 ()) |
| 适用场景 | 复杂逻辑计算、数据筛选、格式化 | 事件处理、非数据驱动的逻辑 |
> 性能对比示例：
> 如果你有一个耗时的循环计算（比如过滤 10000 条数据），使用 computed 只有在数据源变了才算一次；使用 method 只要页面上任何不想干的数据变了引发重绘，它都会跑一遍循环。
> 
5. 最佳实践 (Best Practices)
 * Getter 应该没有副作用：不要在 computed 的 getter 函数里发网络请求、修改 DOM 或者修改其他状态。它应该只是单纯的 计算。
 * 避免过度嵌套：虽然 computed 可以依赖其他 computed，但层级过深会导致代码难以调试（像意大利面条一样）。
6. 计算机底层视角
computed 实现了 惰性求值 (Lazy Evaluation)：
 * 创建时：它不会立刻计算，只是标记为 "Dirty"（脏）。
 * 访问时：
   * 如果是 "Dirty"，运行函数计算，缓存结果，标记为 "Clean"。
   * 如果是 "Clean"，直接返回缓存。
 * 依赖变化时：它不会立刻计算，只是把标记改回 "Dirty"，通知视图需要更新。
