
# 👁️ Vue 3: Watch (监听器) 核心速查

## 1. 🧠 核心心智模型 (Mental Model)

- **本质**：**副作用回调 (Side Effect Callback)**。
    
- **逻辑**：`When (Input Changes) -> Do (Side Effect)`。
    
- **CS 类比**：
    
    - 🗄️ **数据库触发器 (Trigger)**：当表中数据变化时，自动执行一段脚本。
        
    - ⚡ **中断处理 (Interrupt Handler)**：CPU 收到信号，暂停当前任务去处理特定事件。
        
- **核心特征**：
    
    - **惰性 (Lazy)**：默认不执行，只有数据变了才执行 (除非 `immediate: true`)。
        
    - **显式依赖**：你必须明确告诉它盯着“谁”。

## 2. ⚡ 标准代码模板 (Copy-Paste Ready)

`watch` 的核心难点在于 **第一个参数（数据源）** 怎么写。

### 2.1 基础场景 (Ref & Getter)

> **🔥 核心铁律**：监视 `reactive` 对象中的某个**基础类型属性**时，必须写成 **Getter 函数**。

代码段

```
<script setup>
import { ref, reactive, watch } from 'vue'

const count = ref(0)
const user = reactive({ name: 'Alex', age: 18 })

// 1. 监视 Ref -> 直接传变量
watch(count, (newVal, oldVal) => {
  console.log(`Count: ${oldVal} -> ${newVal}`)
})

// 2. 监视 Reactive 的某个属性 -> 必须用 getter 函数 () => ...
// ❌ 错误: watch(user.age, ...) -> 传过去的是个纯数字 18，Vue 无法追踪
// ✅ 正确:
watch(
  () => user.age, 
  (newAge) => console.log('年龄变了:', newAge)
)
</script>
```

### 2.2 进阶配置 (Deep & Immediate)

代码段

```
<script setup>
import { ref, watch } from 'vue'
const state = ref({ id: 1, info: { text: 'hello' } })

watch(state, () => {
  console.log('嵌套属性变化了')
}, { 
  deep: true,      // 强制开启深度监视 (监视 Ref 对象时必须加，Reactive 默认自带)
  immediate: true  // 初始化时立刻执行一次 (例如：进页面就先拉取一次列表)
})
</script>
```

### 2.3 自动收集依赖 (watchEffect)

> **场景**：不想一个个手动列出依赖，且希望立即执行。

代码段

```
<script setup>
import { ref, watchEffect } from 'vue'

const id = ref(1)
const url = ref('https://api.com')

// 自动追踪函数里用到的 id.value 和 url.value
watchEffect(() => {
  // 只要 id 或 url 变了，这行请求就会重新发
  console.log(`GET ${url.value}/users/${id.value}`)
})
</script>
```

## 3. ⚖️ 核心对比：Computed vs Watch

这是架构选型的关键。

|**维度**|**Computed (计算属性)**|**Watch (监听器)**|
|---|---|---|
|**侧重点**|**结果** (我要得到一个新值)|**过程** (我要执行一个动作)|
|**副作用**|❌ **禁止** (纯函数，无副作用)|✅ **允许** (发请求、操作 DOM、定时器)|
|**缓存**|✅ 有缓存 (依赖不变不计算)|❌ 无缓存 (变了就跑)|
|**返回值**|必须 `return`|不需要返回值|
|**典型场景**|购物车总价、筛选列表、样式计算|搜索防抖、路由跳转、数据存 LocalStorage|

## 4. 🛑 避坑指南 (Troubleshooting)

| **场景**          | **❌ 错误写法 / 现象**             | **✅ 正确做法 / 原因**                                                                                         |
| --------------- | --------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Reactive 属性** | `watch(obj.count, fn)`      | `watch(() => obj.count, fn)`<br><br>  <br><br>直接传 `obj.count` 只是传了个数字，丢失了响应性链接。                         |
| **Reactive 深度** | 监视整个 Reactive 对象消耗巨大        | **只监视需要的属性**。<br><br>  <br><br>Reactive 默认强制开启 Deep，大数据量下会递归遍历，性能极差。                                    |
| **Ref 对象深度**    | 修改 `ref({a:1}).value.a` 不触发 | 加 `{ deep: true }`。<br><br>  <br><br>Ref 默认只监视 `.value` 的引用变化（即整体替换）。                                   |
| **停止监听**        | 异步回调中创建的 watch 不会销毁         | `const stop = watch(...)`<br><br>  <br><br>`stop()`<br><br>  <br><br>只有在 setup 同步执行的 watch 才会随组件销毁自动停止。 |

## 5. 🔬 原理深挖 (Deep Dive)

**Vue 是怎么知道该什么时候触发 watch 的？**

1. **Getter 触发依赖收集**：
    
    - 当你写 `() => user.age` 时，Vue 执行了这个函数。
        
    - 读取 `user.age` 触发了 Proxy 的 `get` 拦截器。
        
    - Vue 记录下：“这个 Watcher 依赖于 `user.age`”。
        
2. **Setter 触发通知**：
    
    - 当你执行 `user.age = 20`。
        
    - Proxy 的 `set` 拦截器触发。
        
    - Vue 查找所有依赖 `user.age` 的副作用（包括这个 Watcher），并将它们推入**调度队列 (Scheduler Queue)**。
        
3. **Flush (刷新)**：
    
    - 默认情况下 (`flush: 'pre'`)，Watcher 会在 DOM 更新**之前**执行。
