这份笔记为你整理了 Vue 3 watch (监听器) 的核心机制。
如果说 computed 是为了计算结果（产生新数据），那么 watch 就是为了执行副作用（Side Effects，如发请求、打印日志、操作 DOM）。
# Vue 3: Watch (监听器) 核心速查

## 1. 核心定义 (Mental Model)

* **本质**：它是数据变化的 **“回调机制” (Callback Mechanism)**。
* **逻辑**：`When (Source changes) -> Do (Logic)`。
* **特性**：
    * **惰性 (Lazy)**：默认情况下，只有在数据变化时才执行（除非配置 `immediate`）。
    * **显式依赖**：你需要明确告诉它要“盯着”谁。
* **CS 类比**：
    * 数据库的 **触发器 (Trigger)**。
    * 操作系统中的 **中断处理 (Interrupt Handler)**。

---

## 2. 基础用法 (Usage Patterns)

`watch` 接收三个参数：`watch(source, callback, options)`。

### 2.1 监视 Ref (最简单)
直接把 Ref 变量传进去，**不需要** `.value`。

```vue
<script setup>
import { ref, watch } from 'vue'

const count = ref(0)

// 监视 source
watch(count, (newValue, oldValue) => {
  console.log(`从 ${oldValue} 变更为 ${newValue}`)
})
</script>

2.2 监视 Reactive 的某个属性 (易错点)
如果你要监视 reactive 对象里的某一个属性，必须写成 Getter 函数 的形式。
<script setup>
import { reactive, watch } from 'vue'

const user = reactive({ name: 'Alex', age: 18 })

// ❌ 错误写法：user.age 是一个普通数字，Vue 无法追踪
// watch(user.age, (val) => {}) 

// ✅ 正确写法：使用 getter 函数 (() => user.age)
watch(
  () => user.age, 
  (newAge) => {
    console.log('年龄变了:', newAge)
  }
)
</script>

2.3 监视多个来源
可以使用数组。
watch([x, () => y.value], ([newX, newY]) => {
  console.log(`x变成 ${newX}, y变成 ${newY}`)
})

3. 深度监视与立即执行 (Deep & Immediate)
这是 watch 的第三个参数（配置对象）。
3.1 深度监视 (Deep Watch)
 * 监视 Ref 对象：默认是浅层的。如果 Ref 里包的是对象，对象内部属性变化不会触发。需开启 deep: true。
 * 监视 Reactive 对象：强制开启了深度监视（无法关闭）。
<!-- end list -->
const state = ref({ count: 0 })

watch(state, () => {
  console.log('触发了')
}, { deep: true }) // 如果不加 deep，修改 state.value.count 不会触发

3.2 立即执行 (Immediate)
让回调在侦听器创建时立即执行一次（类似 computed 的行为，常用于初始化发请求）。
watch(source, (val) => {
  fetchData(val)
}, { immediate: true })

4. 变体：watchEffect (自动收集依赖)
如果你懒得一个个写依赖源，可以用 watchEffect。它会立即执行一次函数，并自动追踪函数里用到的所有响应式变量。
<script setup>
import { ref, watchEffect } from 'vue'

const id = ref(1)
const url = ref('[https://api.com](https://api.com)')

// 自动追踪 id.value 和 url.value
// 只要这两个任何一个变了，就会重新执行
watchEffect(() => {
  console.log(`发送请求: ${url.value}/${id.value}`)
})
</script>

5. 决策矩阵：Computed vs Watch
这是高频面试题，也是架构选型的关键。
| 维度 | Computed (计算属性) | Watch (监听器) |
|---|---|---|
| 关注点 | 结果 (我要得到什么值) | 过程 (我要做什么事) |
| 副作用 | ❌ 禁止 (不要发请求/改DOM) | ✅ 允许 (发请求、动画、定时器) |
| 缓存 | ✅ 有缓存 (依赖不变不计算) | ❌ 无缓存 (变了就跑) |
| 返回值 | 必须 return 一个值 | 不需要返回值 |
| 典型场景 | 购物车总价、过滤列表 | 搜索框防抖、路由变化跳转、数据存LS |
6. 避坑指南 (Troubleshooting)
 * Reactive 默认 Deep：监视一个巨大的 reactive 对象非常消耗性能，因为它会递归遍历所有属性。尽量只监视你需要的那一个属性（用 Getter 函数）。
 * watchEffect 的执行时机：默认在 DOM 更新前执行。如果你要在 watchEffect 里操作 DOM，需配置 flush: 'post'。
 * 停止监视：在 setup 中同步创建的 watcher 会随组件销毁自动停止。如果在异步回调里创建 watcher，必须手动停止（调用 watch 返回的那个函数）。
<!-- end list -->
const stop = watch(source, callback)
// 手动停止
stop()
