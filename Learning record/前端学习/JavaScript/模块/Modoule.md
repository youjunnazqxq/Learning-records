
### 📝 JS 模块 (Module) 核心笔记

#### 1. 什么是模块？

模块就像是独立的“积木”。它们可以互相加载，通过特定的指令交换功能。

- **目的：** 将复杂代码拆分，从一个模块调用另一个模块的函数。
    
- **关键词：**
    
    - **`export` (出)：** 标记当前模块中可以被外部访问的变量或函数。
        
    - **`import` (进)：** 允许从其他模块导入功能。
        

**基本语法：**

JavaScript

```
import { 函数名 } from '路径/文件名.js';
```

---

#### 2. 模块的“五大核心机制” (重点背诵)

这里是模块与普通 JS 脚本最本质的区别：

- **🔒 独立的作用域 (Module Scope)**
    
    - **特性：** 模块内部是**封闭**的。
        
    - **表现：** 在模块顶层定义的变量（如 `let x = 10`），只属于这个模块。
        
    - **结果：** 就算两个模块里都有 `x`，它们也互不干扰，完全“隔离”。
        
- **🛡️ 始终使用 "use strict"**
    
    - 模块默认自动开启**严格模式**。你不需要手动写 `"use strict"`，也不能关掉它。
        
- **⚡️ 代码仅在第一次导入时执行 (单例模式)**
    
    - **机制：** 如果同一个模块被 `import` 了 10 次，它的代码**只会跑 1 次**（就是第一次被导入时）。
        
    - **后续：** 后面 9 次导入，拿到的都是第一次运行后导出的**缓存结果**。
        
- **🚫 `this` 是 undefined**
    
    - 在模块的顶层作用域中，`this` 不再指向全局对象（window），而是 `undefined`。
        
- **ℹ️ `import.meta`**
    
    - 这是一个特殊对象，包含模块的元数据。
        
    - **常用：** 获取当前模块文件的 URL。
        

---

#### 3. 在 HTML 中的表现

当你在 HTML 中使用 `<script type="module">` 时：

- **⏳ 默认延迟加载 (Deferred)**
    
    - **特性：** 不会阻塞 HTML 的解析。
        
    - **效果：** 相当于给普通脚本加了 `defer` 属性。浏览器会一边解析 HTML，一边并行下载模块，等 HTML 解析完了再执行模块代码。
