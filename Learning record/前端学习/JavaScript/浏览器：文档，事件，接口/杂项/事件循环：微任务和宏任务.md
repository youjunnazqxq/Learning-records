#### 事件循环 (Event Loop) 的规则：

JavaScript 的事件循环有一个铁律： **在执行_下一个_宏任务之前，必须_清空_所有微任务**




# 事件循环 


**事件循环** 的概念非常简单。它是一个在 JavaScript 引擎等待任务，执行任务和进入休眠状态等待更多任务这几个状态之间转换的无限循环。

引擎的一般算法：

1. 当有任务时：
    - 从最先进入的任务开始执行。
2. 休眠直到出现任务，然后转到第 1 步



 
-  macrotask queue （宏任务队列）：
它是用来存放“宏任务”的队列。宏任务是JS中一类异步任务，图里的 script （页面初始的整个脚本代码）、 mousemove （DOM事件回调）、 setTimeout （定时器回调）都是常见的宏任务类型（还包括setInterval、I/O操作等）。
-  event loop （事件循环）：
这是浏览器/Node.js处理异步任务的“循环机制”——它会持续不断地从宏任务队列中取出任务执行，执行完一个宏任务后，再处理后续的宏任务，以此循环。
 
#### 两个细节 

1. 引擎执行任务时永远不会进行渲染（render）。如果任务执行需要很长一段时间也没关系。仅在任务完成后才会绘制对 DOM 的更改。
2. 如果一项任务执行花费的时间过长，浏览器将无法执行其他任务，例如处理用户事件。因此，在一定时间后，浏览器会抛出一个如“页面未响应”之类的警报，建议你终止这个任务。这种情况常发生在有大量复杂的计算或导致死循环的程序错误时。

# 用例1 拆分cpu过载任务 

```
let i = 0;
let start = Date.now();

function count() {
  // 将调度（scheduling）移动到开头
  if (i < 1e9 - 1e6) {
    setTimeout(count); // 安排（schedule）新的调用
  }

  do {
    i++;
  } while (i % 1e6 != 0);

  if (i == 1e9) {
    alert("Done in " + (Date.now() - start) + 'ms');
  }
}

count();


```

# 宏任务和微任务


[微任务（Microtask）](https://zh.javascript.info/microtask-queue) 一章中提到的 **微任务（microtask）**。

微任务仅来自于我们的代码。它们通常是由 promise 创建的：对 `.then/catch/finally` 处理程序的执行会成为微任务。微任务也被用于 `await` 的“幕后”，因为它是 promise 处理的另一种形式。

还有一个特殊的函数 `queueMicrotask(func)`，它对 `func` 进行排队，以在微任务队列中执行。

**每个宏任务之后，引擎会立即执行微任务队列中的所有任务，然后再执行其他的宏任务，或渲染，或进行**


微任务会在执行任何其他事件处理，或渲染，或执行任何其他宏任务之前完成
