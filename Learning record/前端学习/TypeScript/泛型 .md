
### 1. 为什么要用泛型？(告别 `any`)

文档开篇给出了一个痛点：如果你想写一个通用的“创建数组”函数。

- **不用泛型**：你只能用 `any`。
    
    TypeScript
    
    ```
    // 缺点：TS 此时“瞎了”，根本不管你里面装的是数字还是字符串
    function createArray(value: any, count: number): any[] { ... }
    ```
    
    _后果_：写代码时没有提示，写错方法（比如对数字调用 `split`）编译器也不报错，只有运行才会炸。
    
- **使用泛型**：你挖了一个坑 `<T>`，告诉 TS “这里以后会填一种具体的类型”。
    
    TypeScript
    
    ```
    // T 是占位符，类似 Java 的 <T>
    function createArray2<T>(value: T, count: number): Array<T> { ... }
    ```
    
    _优势_：当你填入 `<string>` 后，TS 就会立刻知道返回的数组里全是字符串，你敢调 `toFixed()` 它就敢报错。
    

---

### 2. 泛型函数 (Generic Functions)

写法和 Java 方法几乎一致，只是 TS 的类型推导更强。

- **定义**：在函数名后面加 `<T>`。
    
    TypeScript
    
    ```
    function swap<K, V>(a: K, b: V): [K, V] {
        return [a, b];
    }
    ```
    
- **使用**：
    
    - **显式指定**（文档写法）：`createArray2<number>(11, 3)`。
        
    - **自动推导**（TS 强项）：通常你不需要写 `<number>`，TS 会根据你传的参数 `11` 自动猜出 `T` 是 `number`。

### 3. 泛型接口与类 (Interfaces & Classes)

这一部分完全是 Java DAO 模式的复刻。文档中的 `UserCRUD` 例子对你来说应该极其眼熟。

**场景**：定义一个通用的增删改查（CRUD）接口。

TypeScript

```
// 1. 定义泛型接口
interface IbaseCRUD<T> {
  data: T[];
  add: (t: T) => void;
  getById: (id: number) => T;
}

// 2. 具体类实现泛型接口 (完全是 Java 语法)
class UserCRUD implements IbaseCRUD<User> {
  data: User[] = []; // 这里 T 变成了 User
  
  add(user: User): void { ... }
  getById(id: number): User { ... }
}
```

这展示了泛型最经典的作用：**约束类的一致性**。

### 4. 泛型约束 (Generic Constraints) —— `extends`

这是 TS 和 Java 略有不同的地方。

- **问题**：在 Java 里，如果你想调用泛型对象的方法，你可能需要 `T extends SomeClass`。
    
- **TS 的问题**：如果你写 `function fn<T>(x: T) { console.log(x.length) }`，TS 会报错。因为它不知道这个 `T` 到底有没有 `length` 属性（万一 `T` 是 `number` 呢？）。
    
- **解决方法**：使用 `extends` 关键字，但后面通常跟的是一个**接口（Interface）**，用来描述“**必须要有这些属性**”。
    

TypeScript

```
// 1. 定义一个“约束条件”：必须得有 length 属性
interface Lengthwise {
  length: number;
}

// 2. 施加约束
// 翻译：T 可以是任何类型，但必须包含 Lengthwise 定义的结构
function fn2<T extends Lengthwise>(x: T): void {
  console.log(x.length); // ✅ 现在安全了
}

fn2('abc'); // ✅ 字符串有 length，通过
// fn2(123);   // ❌ 数字没有 length，报错
```

### 总结：TS 泛型 vs Java 泛型

|**特性**|**TypeScript**|**Java**|**你的理解**|
|---|---|---|---|
|**声明方式**|`<T>`|`<T>`|一模一样|
|**使用位置**|函数、接口、类、类型别名|方法、接口、类|TS 多了一个 `type` 别名支持泛型|
|**约束关键字**|`T extends Interface`|`T extends Class/Interface`|TS 的约束是基于**结构**的（只要有那个属性就行）|
|**类型擦除**|**是**|**是**|编译后泛型信息都会消失，运行时不存在|

1. 基础类型 (`string` vs `String`)
    
2. 接口 (`interface` 结构化类型)
    
3. 函数 (可选参数、重载假象)
    
4. 类 (`public` 默认、参数属性语法糖)
    
5. 泛型 (`<T>`, `extends` 约束)
