

### 1. 左半部分：`[key: string]`

- **含义**：这规定了该对象的**“键名（属性名）”必须是字符串类型**。
    
- **细节**：这里的 `key` 其实只是一个随意的占位符名字。你把它写成 `[name: string]`、`[propName: string]` 甚至 `[dog: string]` 在语法上都是完全一样的。它只是告诉 TypeScript：“无论将来谁往这个对象里塞属性，属性的名字必须是字符串。”
    

### 2. 右半部分：`: string[]`

- **含义**：这规定了前面那个键所对应的**“值”，必须是一个由字符串组成的数组**。

### 结合真实业务场景来理解

回到咱们 `geeker-admin` 的按钮权限仓库。想象一下，一个后台系统有成百上千个页面，每个页面的按钮权限都不一样。

如果我们用**写死（静态）**的方式来定义接口，可能会长这样：

TypeScript

```
interface AuthButtonList {
  UserMenu: string[];    // 用户管理页面的权限
  RoleMenu: string[];    // 角色管理页面的权限
  // ...如果有 100 个页面，难道要在这里手写 100 行吗？
}
```

这显然是不现实的，因为页面的名字（路由名）是动态从后端拉取回来的。

所以，作者使用了**索引签名**：

TypeScript

```
authButtonList: { [key: string]: string[] }
```

这就像是制定了一个“万能容器”的规则：**“我不管你将来往这里面塞什么名字的页面，只要页面的名字是字符串，并且它对应的权限列表是一个字符串数组，我都合法放行。”**

于是，后端返回下面这种灵活的 JSON 数据时，TypeScript 就能完美校验并接收了：

JSON

```
{
  "UserMenu": ["add", "edit", "delete", "import"],
  "RoleMenu": ["add", "export"],
  "OrderMenu": ["view"]
}
```

**一句话总结：**

`[key: string]: string[]` 就是在定义一个**动态键名的字典对象**，键是字符串，值是字符串数组。
