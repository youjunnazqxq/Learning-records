

### 1. 接口 (Interface) —— "数据的形状"

在 TypeScript 中，Interface 主要用来定义 **对象看起来应该是什么样（Shape）**，而不是像 Java 那样强制绑定一个类。

- **核心理念**：**结构化类型 (Structural Typing)**。
    
    - _口诀_：“只要长得像，就是它。”（不需要显式 `implements`）。
        
- **写法**：
    
    TypeScript
    
    ```
    interface User {
        name: string;
        age: number;
    }
    ```
    
- **与 Java 的区别**：
    
    1. **纯编译时概念**：编译成 JS 后，Interface 代码会**完全消失**（不能用反射）。
        
    2. **不仅限类**：通常直接用于约束 **JSON 对象** 或 **函数参数**。
        
    3. **灵活性**：支持可选属性、任意属性等动态特性。
        

---

### 2. 可选值 (`?`) —— "可有可无"

解决了 Java 中处理 `null` 或 "非必填字段" 的痛点。

- **语法**：在属性名或参数名后面加 `?`。
    
    - `email?: string`
        
- **本质**：等同于 **联合类型** `Type | undefined`。
    
    - 意思是：要么是这个类型，要么是 `undefined`（不存在）。
        
- **使用场景**：
- 
    
    |**场景**|**写法**|**说明**|
    |---|---|---|
    |**接口属性**|`interface User { email?: string; }`|这个 JSON 对象可以没有 `email` 字段。|
    |**函数参数**|`function log(msg?: string) { ... }`|调用时可以不传参数：`log()`。|
    

---

### 3. 黄金搭档：可选链 (`?.`)

既然定义了“可选”，使用时就要防备它为空。TS 提供了和 Java `Optional` 类似的语法糖，但更简洁。

- **语法**：`对象?.属性`
    
- **作用**：**如果前面是 null/undefined，这就停下返回 undefined；否则继续取值。**
    
- **对比**：
    
    - **Java**: `if (user != null && user.address != null) { ... }`
        
    - **TS**: `user?.address?.city` (一行搞定，不会报空指针异常)
        

---

### 📝 综合代码示例（可直接抄录）

TypeScript

```
// 1. 定义形状
interface Config {
    url: string;        // 必填
    timeout?: number;   // 可选：不填默认就是 undefined
    retry?: boolean;    // 可选
}

// 2. 使用形状
function connect(config: Config) {
    // 3. 安全读取可选值 (?.): 如果 config.retry 没传，就取 false
    // ?? 是空值合并运算符，类似 Java 的 getOrDefault
    const shouldRetry = config.retry ?? false; 
    
    console.log("Connecting to:", config.url);
}

// ✅ 合法：只传必填项
connect({ url: "https://api.com" });

// ✅ 合法：传了可选顶
connect({ url: "https://google.com", timeout: 5000 });
```
