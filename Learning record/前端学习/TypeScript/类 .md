基于你上传的笔记 `3_class.md` 和代码截图，结合你的 Java 背景，以下是 TypeScript 中 **类 (Class)** 的核心总结。

TS 的类是基于 ES6 标准实现的，它的语法设计深受 Java 和 C# 的影响，所以你上手会非常快。

### 1. 基本定义 (Basic Definition)

结构和 Java 几乎一模一样，由属性、构造函数和方法组成。

- **基本语法**：使用 `class` 关键字。
    
- **成员访问**：在类内部访问成员属性或方法时，**必须**使用 `this`。
    
- **构造函数**：关键字是 `constructor`（Java 中是类名）。
    

TypeScript

```
class Greeter {
  message: string; // 声明属性

  constructor(message: string) {
    this.message = message;
  }

  greet(): string {
    return 'Hello ' + this.message;
  }
}
// 实例化
const greeter = new Greeter('world'); //
```

### 2. 继承 (Inheritance)

TS 使用基于类的继承，关键词也和 Java 一样。

- **关键字**：使用 `extends` 实现继承。
    
- **Super 调用**：
    
    - 子类如果写了构造函数，**必须**在访问 `this` 之前调用 `super()`。
        
    - 在普通方法中，使用 `super.method()` 调用父类方法。
        
- **重写 (Override)**：子类可以直接重写父类的方法。
    
- **多态**：父类型的引用可以指向子类型的实例（如 `const tom: Animal = new Horse('ho22')`）。
    

### 3. 访问修饰符 (Access Modifiers)

这里有一个与 Java 最大的不同点：**默认是 Public**。

|**修饰符**|**描述**|**Java 对比**|
|---|---|---|
|**`public`**|**默认值**。可以在任何地方访问。|Java 默认为包可见 (package-private)，TS 默认为 public。|
|**`private`**|只能在声明它的**类内部**访问。|与 Java 一致。|
|**`protected`**|可以在类内部及其**子类**中访问。|与 Java 类似，但 TS 的 protected 不包含包访问权限概念。|

### 4. 特殊修饰符与语法糖

#### `readonly` 修饰符

- 表示属性是**只读**的。
    
- 只能在**声明时**或**构造函数**里初始化。
    

#### 参数属性 (Parameter Properties) —— **TS 特有语法糖**

这是 Java 没有的特性，非常省代码。你可以在构造函数的参数前直接加修饰符，TS 会自动帮你把这个参数声明为类的属性并赋值。

- **传统写法**：声明属性 -> 构造函数传参 -> `this.x = x`。
    
- **TS 简写**：
    
    TypeScript
    
    ```
    class Person2 {
      // 一步完成：声明属性 name + 设为只读 + 构造函数赋值
      constructor(readonly name: string) { 
      }
    }
    ```
    
    这等同于在类里声明了一个 `readonly name` 属性并在构造函数里赋值。
    

### 5. 存取器 (Getters / Setters)

使用 `get` 和 `set` 关键字来拦截对属性的访问。这比 Java 手写 `getField()` / `setField()` 更像属性访问。

TypeScript

```
class Person {
  // ...
  get fullName() { return ... }
  set fullName(value) { ... }
}
// 调用时像访问普通属性一样，不需要加括号
p.fullName = 'E-F';
```

### 6. 静态属性 (Static)

- 使用 `static` 关键字。
    
- 属性存在于**类本身**上，而不是实例上。
    
- **访问方式**：`ClassName.propertyName`（如 `Grid.xxx`），而不是 `this.xxx`。
    

### 7. 抽象类 (Abstract Class)

- 使用 `abstract` 关键字。
    
- **特点**：
    
    - 不能被实例化。
        
    - 可以包含具体实现的方法，也可以包含抽象方法（只有签名，没有实现）。
        
    - 抽象方法必须在子类中实现。
        

**总结**：TS 的类机制几乎复刻了 Java 的面向对象特性（继承、封装、多态、抽象），同时增加了一些简化开发的语法糖（如参数属性）。对于 Java 开发者来说，这是最容易通过的部分。
