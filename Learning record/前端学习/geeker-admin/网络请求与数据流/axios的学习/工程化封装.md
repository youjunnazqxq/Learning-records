好，我们要进入正题了。这就是**普通切图仔**和**前端工程师**的分水岭。

在 `geeker-admin` 这种企业级项目中，你打开 `src/api/index.ts` (或者 `src/utils/http/index.ts`)，看到的绝对不是简单的 `axios.get`，而是一套严密的**流水线**。

我们把这套流水线称为 **Axios 的二次封装**。

这套封装通常包含三个核心步骤：

1. **实例化**：造一个专属的 HTTP 客户端。
    
2. **请求拦截**：在请求发出去之前，“动手动脚”。
    
3. **响应拦截**：在数据拿回来之后，“验货处理”。
    

为了让你看懂 `geeker-admin` 的源码，我把代码拆解成最核心的骨架给你看。

---

### 第一步：实例化 (The Instance)

这步我们刚才讲过了，但在工程化中，我们会引入**环境变量**。

JavaScript

```
import axios from "axios";

// 这里的 import.meta.env.VITE_API_URL 是 Vite 提供的环境变量
// 开发时可能是 "/api"，上线后可能是 "https://admin.geeker.com/api"
const config = {
  baseURL: import.meta.env.VITE_API_URL,
  timeout: 10000,
  withCredentials: true
};

const service = axios.create(config);
```

---

### 第二步：请求拦截器 (Request Interceptor)

**这是“安检口”。** 所有请求出发前，必须经过这里。

在 `geeker-admin` 中，这里主要做两件事：

1. **加 Token**：不管是查用户还是删商品，都要把身份证明带上。
    
2. **开 Loading**：请求一开始，让全屏出现一个转圈圈的动画，防止用户乱点。
    

JavaScript

```
import { useUserStore } from "@/stores/modules/user";
import { showFullScreenLoading } from "@/config/serviceLoading";

// service.interceptors.request.use(成功的回调, 失败的回调)
service.interceptors.request.use(
  (config) => {
    // 1. 开启全屏 Loading 动画
    showFullScreenLoading();

    // 2. 从 Pinia (状态管理) 中获取 Token
    const userStore = useUserStore();
    const token = userStore.token;

    // 3. 如果有 Token，就加到 Header 里
    // 以后你写具体的接口时，完全不用操心 token 的事，这里自动加好了
    if (token) {
      config.headers.Authorization = "Bearer " + token;
    }

    return config; // 必须返回配置，否则请求就发不出去了！
  },
  (error) => {
    return Promise.reject(error);
  }
);
```

**关键点：** 这一步实现了**无感认证**。你在写业务代码时，完全感觉不到 Token 的存在，但它确实每次都带上了。

---

### 第三步：响应拦截器 (Response Interceptor)

**这是“验货区”。** 后端的数据回来了，但还没到你的组件里。

这里主要做三件事：

1. **关 Loading**：数据回来了，把转圈圈关掉。
    
2. **脱壳**：只返回 `data`，把 `axios` 包装的那层壳扔掉。
    
3. **统一错误处理**：这是最复杂的。
    

JavaScript

```
import { tryHideFullScreenLoading } from "@/config/serviceLoading";
import { checkStatus } from "./checkStatus"; // 封装好的错误检查函数
import { ElMessage } from "element-plus";

service.interceptors.response.use(
  (response) => {
    const { data } = response;
    
    // 1. 关闭 Loading
    tryHideFullScreenLoading();

    // 2. 业务逻辑判断 (跟后端约定的规矩)
    // 假设后端约定：code == 200 才是成功，其他都是失败
    if (data.code === 200) {
      return data.data; // 脱壳：直接把核心数据给你
    } 
    
    // 3. 业务错误处理 (比如 code 401 代表 token 过期)
    if (data.code == 401) {
        useUserStore().logout(); // 强制登出
        return Promise.reject(data.msg);
    }

    // 其他错误直接弹窗提示
    ElMessage.error(data.msg);
    return Promise.reject(data);
  },
  
  (error) => {
    // 4. HTTP 错误处理 (这里处理 404, 500, 网络断开等)
    const { response } = error;
    tryHideFullScreenLoading();
    
    // 如果有响应（服务器回话了，但是是报错）
    if (response) {
       // checkStatus 是一个 switch-case 函数，把 404 转成 "资源未找到"，500 转成 "服务器错误"
       checkStatus(response.status); 
    } else {
       // 如果连响应都没有（比如断网了）
       if (!window.navigator.onLine) return ElMessage.error("网络连接失败");
    }
    
    return Promise.reject(error);
  }
);
```

### 第四步：Geeker-Admin 的“类”封装 (Class Wrapper)

这一点非常重要。

你在 `geeker-admin` 里看到的可能不是上面直接 `export service`，而是**封装成了一个类**。

**为什么要这么做？**

为了更好地利用 TypeScript 的提示，并且让代码看起来更整洁。

它的大致结构是这样的：

TypeScript

```
// 这就是你在 geeker-admin 里实际使用的那个类
class RequestHttp {
  service: AxiosInstance;

  constructor(config: AxiosRequestConfig) {
    // 实例化 axios
    this.service = axios.create(config);
    
    // ... 这里配置上面的拦截器 ...
  }

  // 封装常用的方法，让它们更好用
  get<T>(url: string, params?: object, _object = {}): Promise<T> {
    return this.service.get(url, { params, ..._object });
  }

  post<T>(url: string, params?: object | string, _object = {}): Promise<T> {
    return this.service.post(url, params, _object);
  }
  
  // ... put, delete, download ...
}

export default new RequestHttp(config);
```

**这样封装后，你在页面里用起来就超爽：**

JavaScript

```
import http from "@/api"; // 引入上面导出的实例

// 获取用户列表
// <UserRes> 是 TS 泛型，告诉 VSCode 返回的数据长什么样，会有自动补全！
export const getUserList = (params) => {
  return http.get<UserRes>("/user/list", params);
};
```

### 总结 Layer 2

**工程化封装的核心价值：**

1. **自动化**：Token 自动加，Loading 自动开关，错误自动弹窗。
    
2. **标准化**：不管后端返回什么鬼样子，回到组件里的数据格式是统一的。
    
3. **类型化**：(TS) 让你在写代码时能点出属性来。

打开 `geeker-admin` 的项目，找到 `src/api/index.ts`（或者类似的各种 helper 文件）。

你会发现里面密密麻麻的代码，无非就是我上面讲的这三块：

1. `axios.create`
    
2. `interceptors.request`
    
3. `interceptors.response`
