没问题，我们来把 **请求头（Request Headers）** 彻底拆解一下。

如果在之前的比喻中：

- **URL** 是收件人地址。
    
- **Body (`data`)** 是包裹里的货物。
    
- **Params** 是写在信封背面的备注。
    

那么 **请求头 (`headers`)** 就是贴在包裹上的 **“物流标签”** 和 **“通行证”**。

它是写给 **快递员（浏览器）** 和 **收件人（服务器）** 看的 **元数据（Meta-data）**。虽然它不是货物本身，但没有它，货物可能送不到，或者对方拒收。

在 `geeker-admin` 和大多数现代 Web 开发中，你只需要关注 **这三个最核心的请求头**：

---

### 1. `Content-Type`: 告诉服务器“我发的是什么”

这是最重要的头。当你发送 POST/PUT 请求（带 Body）时，服务器是瞎的。它不知道你发过来的是一段文本、一张图片、还是一个 JSON 对象。

你需要通过 `Content-Type` 告诉它。

#### A. `application/json` (最常用)

- **含义**：“我发给你的是 JSON 格式的数据”。
    
- **样子**：Body 里长这样 `{"name": "Jack", "age": 18}`。
    
- **Axios**：这是 Axios 的**默认值**。你不需要特意去写，除非被改过。
    
- **场景**：95% 的业务场景（增删改查）。
    

#### B. `multipart/form-data` (文件上传)

- **含义**：“我发给你的是文件（二进制流），而且可能混杂着文本”。
    
- **样子**：浏览器会自动把数据切成一块一块的，用 `boundary` 分隔。
    
- **Axios**：当你使用 `FormData` 对象上传文件时，浏览器会自动帮你设置这个头，通常不需要手动写，或者手动写上以防万一。
    
- **场景**：上传头像、上传 Excel。
    

#### C. `application/x-www-form-urlencoded` (老式表单)

- **含义**：“我发的是像 URL 参数那样的键值对”。
    
- **样子**：Body 里长这样 `name=Jack&age=18`。
    
- **Axios**：现在很少用了，除非对接一些很古老的后端系统。
    

---

### 2. `Authorization`: 你的“工牌” (通行证)

在 `geeker-admin` 这种后台管理系统中，这个头是**绝对核心**。

- **含义**：“我是谁，我有权限访问”。
    
- **场景**：除了“登录接口”本身，其他的接口（获取用户列表、删除商品）都需要带上这个头。
    
- **格式**：通常是 `Bearer <token>`。
    
    - `Bearer` 是一种认证规范（意思是“持有者”）。
        
    - `<token>` 是你登录成功后，后端发给你的那串乱码字符串。
        

**代码大概长这样：**

JavaScript

```
headers: {
  'Authorization': 'Bearer eyJhbGciOiJIUzI1NiIsR5cCI6IkpXVCJ9...'
}
```

**注意**：如果这个头没带或者 Token 过期了，后端通常会直接甩回一个 **401 (Unauthorized)** 状态码，然后前端把你踢回登录页。

---

### 3. 自定义 Header: 你们之间的“暗号”

除了上面标准的，你和后端还可以约定一些私有的头。

- **`X-Requested-With`: `XMLHttpRequest`** (判断是否是 Ajax 请求)。
    
- **`Accept-Language`: `zh-CN`** (告诉后端：请给我返回中文的报错信息)。
    
- **`token`: `...`** (有的后端不用 Authorization 标准字段，喜欢自己造一个叫 token 或 x-token 的头)。
    

---

### 4. 在 Axios 中如何配置 Header？

这里有三个级别，优先级 **从低到高**（后面的覆盖前面的）：

#### 级别 1：全局默认（不推荐）

影响整个项目的所有请求。

JavaScript

```
axios.defaults.headers.common['Authorization'] = AUTH_TOKEN;
```

#### 级别 2：实例默认（推荐，geeker-admin 的做法）

只影响这个实例发出的请求。

JavaScript

```
const service = axios.create({
  baseURL: '/api',
  headers: { 
    // 这里设置通用的，比如大家都用 JSON
    'Content-Type': 'application/json'
  }
});
```

#### 级别 3：单次请求覆盖（最强）

只影响这一条请求。

JavaScript

```
// 比如这个上传文件的接口，我要覆盖默认的 Content-Type
service.post('/upload', formData, {
  headers: {
    'Content-Type': 'multipart/form-data' // 覆盖掉实例里的 application/json
  }
});
```

---

### 5. 结合 Geeker-Admin 的思考

现在你再回想一下，为什么我们需要 **拦截器 (Interceptors)**？

你不可能在每一个页面（级别 3）都手写一遍 `'Authorization': token`，对吧？那样太累了。

你也不能写在 `axios.create`（级别 2）里，因为**项目刚启动的时候，用户还没登录，你根本拿不到 Token**。

**这就是拦截器存在的最大意义：**

它允许我们在 **请求发出的那一瞬间（动态）**，去浏览器缓存里查一下有没有 Token。如果有，就临时把它贴到 Header 上；如果没有，就不贴。

**总结请求头：**

它是**告知服务器“我是谁”以及“我发的是什么”的元数据**。
