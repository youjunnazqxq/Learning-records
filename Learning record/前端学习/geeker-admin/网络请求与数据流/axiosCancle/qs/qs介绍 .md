简单来说，**qs** 是前端开发中专门处理 **URL 参数字符串**（Query String）的“专业翻译官”。

在 Geeker-Admin 的网络请求封装中，它主要负责以下两个核心工作：

---

### 1. 序列化 (Stringify)：将对象转为字符串

当你向后端发送请求（尤其是 GET 请求或某些特殊的 POST 请求）时，数据通常需要拼接在网址后面，或者以特定的格式发送。

- **原始数据**：`{ name: "jack", age: 18 }`
    
- **qs 处理后**：`"name=jack&age=18"`
    
- **作用**：它能把复杂的 JS 对象自动转换成后端服务器能识别的标准字符串格式。
    

### 2. 解析 (Parse)：将字符串转回对象

这与上面的过程相反。

- **原始字符串**：`"name=jack&age=18"`
    
- **qs 处理后**：`{ name: "jack", age: 18 }`
    
- **作用**：当你从网址（URL）里获取参数时，它能帮你把那些乱糟糟的字符变回好用的 JS 对象。
    

---

## 💡 为什么 Geeker 必须用它？

虽然浏览器自带了一个 `JSON.stringify`，但 `qs` 有几个不可替代的优势：

- **处理数组更专业**：
    
    - 如果你有一个数组 `[1, 2]`，`qs` 可以根据后端的喜好把它变成 `ids[]=1&ids[]=2` 或者 `ids=1&ids=2`。你截图里的 `arrayFormat: "repeat"` 就是在设置这种规则。
        
- **处理嵌套对象**：
    
    - 对于 `{ user: { name: "jack" } }` 这种深层数据，`qs` 也能完美转化。
        
- **安全可靠**：
    
    - 它会自动处理中文乱码、特殊符号（如 `&`, `=`, `?`）的转义，确保数据在网络传输中不出错。
        

---

## 🛠️ 在 Geeker 项目中的具体表现

正如你刚才看到的代码：

`return qs.stringify(obj, { ..., sort: (a, b) => a.localeCompare(b) });`

这里利用 `qs` 的**序列化**功能，通过**排序**逻辑，为每一个请求生成了一张唯一的“身份证”。这样 `axiosCancel.ts` 才能准确判断两个请求内容是否完全一致，从而决定要不要取消重复的请求。
