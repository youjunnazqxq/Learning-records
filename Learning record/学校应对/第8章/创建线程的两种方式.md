使用你创建的线程类非常简单，但有一个**千万要注意的“陷阱”**。

具体的使用方法取决于你是用哪种方式创建的线程类（继承 `Thread` 还是实现 `Runnable`）。

### 1. 核心口诀

不管用哪种方式，启动线程的金科玉律是：

“创建对象，调用 start()，千万别直接调 run()！”

---

### 2. 具体使用步骤

#### 情况 A：如果你是继承了 `Thread` 类

假设你的类叫 `MyThread extends Thread`。

- **步骤**：直接 `new` 出来，然后调 `start()`。
    
- **代码**：
    
    Java
    
    ```
    public class Main {
        public static void main(String[] args) {
            // 1. 实例化你的线程对象
            MyThread t1 = new MyThread();
    
            // 2. 启动线程 (告诉 CPU：准备好，去执行这个线程的 run 方法)
            t1.start(); 
    
            // 注意：此时主线程 main 会继续往下跑，不会等 t1
            System.out.println("主线程继续执行...");
        }
    }
    ```
    

#### 情况 B：如果你是实现了 `Runnable` 接口 (更常用)

假设你的类叫 `MyTask implements Runnable`。你创建的这个类只是一个“任务清单”，它自己不是线程，必须找个“工人”（Thread）来执行它。

- **步骤**：先 `new` 你的任务，再 `new` 一个 `Thread` 并在构造函数里把任务传进去，最后调 `Thread` 的 `start()`。
    
- **代码**：
    
    Java
    
    ```
    public class Main {
        public static void main(String[] args) {
            // 1. 实例化你的任务对象
            MyTask task = new MyTask();
    
            // 2. 创建一个真正的线程对象，把任务交给它
            // 理解为：招聘一个新工人(thread)，把任务清单(task)给他
            Thread t1 = new Thread(task);
    
            // 3. 启动线程
            t1.start();
        }
    }
    ```
    

---

### 3. 最容易犯的错误：为什么不能直接调 `run()`？

很多初学者会写成 `t1.run()`，虽然代码能跑，但**这完全错了**。

- 调用 run()：
    
    这只是一个普通的方法调用。就好比你（主线程）亲自去干活。主线程必须等 run() 里的代码执行完，才能继续往下走。此时并没有新线程产生，还是单线程。
    
- 调用 start()：
    
    这是启动线程。就好比你（主线程）雇了一个新员工，让他去干活。你喊了一声“开始”，然后你就可以立刻去干别的事了，不用等他。此时才是真正的多线程。
    

### 总结

1. **实例化**：`new` 出你的对象。
    
2. **如果是 Runnable**：记得把它塞给 `new Thread(task)`。
    
3. **启动**：一定要用 **`.start()`**。
