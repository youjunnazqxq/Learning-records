**“中断”（Interrupt）** 是 Java 多线程中一个非常重要，但也最容易被误解的概念。

很多初学者以为调用了 interrupt()，线程就会像踩了急刹车一样立刻停下来。

大错特错！

为了让你彻底明白，请记住这句话：

Java 的中断，不是“命令”，而是一种“协商”或者“通知”。

我把它比作**“叫人吃饭”**，分为两种情况：

---

### 1. 情况一：线程正在“干活”（运行状态）

假设你的线程正在疯狂做数学计算（也就是在跑 `run` 里的循环代码）。

- **你的操作**：调用 `t1.interrupt()`。
    
    - 这就好比你拍了一下正在写作业的张三的肩膀，说：“喂，别写了，吃饭了。”
        
- **线程的反应**：
    
    - **默认情况**：张三**根本不理你**，继续写作业（继续跑循环）。Java 不会强制终止正在运行的线程（为了数据安全）。
        
    - **正确做法**：张三必须自己时不时地抬头看看（**代码里要自己检查中断标记**），如果看到你叫他了，他自己决定收笔不写了。
        

**代码演示：**

Java

```
Thread t1 = new Thread(() -> {
    // 必须自己在循环里检查！否则 interrupt() 毫无作用
    while (!Thread.currentThread().isInterrupted()) {
        System.out.println("我在狂算数学题...");
    }
    System.out.println("哦，看到中断信号了，我自己收拾书包下班。");
});

t1.start();
Thread.sleep(100);
t1.interrupt(); // 发送通知
```

---

### 2. 情况二：线程正在“睡觉/等待”（阻塞状态）

这是你刚学过的 `sleep()` 和 `wait()` 的重灾区。

假设你的线程正在 `Thread.sleep(10000)`（睡 10 秒）。

- **你的操作**：调用 `t1.interrupt()`。
    
    - 这就好比张三正在睡觉，你直接**一盆凉水泼过去**（或者猛摇他）。
        
- **线程的反应**：
    
    - 张三会**惊醒**！
        
    - **表现**：`sleep()` 或 `wait()` 方法会立刻抛出 **`InterruptedException`**（中断异常）。
        
    - **重要细节（必考坑点）**：张三被吓醒后，会**忘记**自己曾经被打断过（**中断标记会被自动清除/重置为 false**）。
        

**代码演示：**

Java

```
Thread t1 = new Thread(() -> {
    try {
        System.out.println("我要睡10秒...");
        Thread.sleep(10000); // 正在这里阻塞
        System.out.println("睡醒了");
    } catch (InterruptedException e) {
        // 1. 被人泼冷水惊醒了，进入这里
        System.out.println("谁打断我睡觉？！");
        
        // 2. 【大坑】此时中断标记已经被清除了（变成了 false）
        // 如果你需要让上层知道这个线程被中断过，通常需要再次手动 interrupt 自己
        // Thread.currentThread().interrupt(); 
    }
});

t1.start();
Thread.sleep(100);
t1.interrupt(); // 泼冷水
```

---

### 3. 三个核心方法（容易晕）

|**方法**|**作用**|**说明**|
|---|---|---|
|**`t1.interrupt()`**|**动手**|给 t1 发个信号（把标记设为 true）。如果 t1 在睡觉，就弄醒它抛异常。|
|**`t1.isInterrupted()`**|**查看**|只是看一眼标记是 true 还是 false。**不会清除标记**。|
|**`Thread.interrupted()`**|**查看并清除**|(静态方法) 查看当前线程有没有被中断，看完了顺手**把标记擦掉**（重置为 false）。**慎用！**|

---

### 总结：为什么要设计得这么麻烦？

你可能会问：_“为什么不直接提供一个 `stop()` 方法，一调用线程就死掉，多省事？”_

Java 早期确实有 `stop()` 方法，但现在被**废弃**了。

- **原因**：强行杀死线程太危险。
    
- **比喻**：就像你正在做一个复杂的转账操作（从 A 扣钱，还没来得及给 B 加钱），突然被一枪毙了。
    
- **后果**：钱扣了，对方没收到，数据彻底坏了（数据不一致）。
    

所以，Java 选择用 “中断（协商）” 机制：

“我想让你停，但我只给你发个信号，至于你什么时候停、怎么收拾残局（释放锁、保存数据），由你自己决定。”
