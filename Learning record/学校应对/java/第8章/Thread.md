`Thread` 类提供了很多方法来管理线程的生命周期、优先级和状态。为了方便记忆，我们可以把它们分为 **4 大类**：

### 1. 获取信息与属性设置 (我是谁？)

这些方法主要用来查看线程的状态，或者给线程打标签，方便调试。

- **`static Thread currentThread()`** 【**最常用**】
    
    - **作用**：获取**当前正在执行**这段代码的那个线程对象。
        
    - **场景**：你要在 `run()` 方法里打印日志，想知道现在是哪个线程在跑，就用它。
        
    - `System.out.println("当前线程是：" + Thread.currentThread().getName());`
        
- **`String getName()` / `void setName(String name)`**
    
    - **作用**：获取或设置线程的名字。
        
    - **建议**：创建线程时最好给个有意义的名字（比如 "下载线程-1"），否则报错时全是 "Thread-0", "Thread-1"，很难排查问题。
        
- **`boolean isAlive()`**
    
    - **作用**：判断线程是否还“活着”。
        
    - **定义**：从调用 `start()` 开始，到 `run()` 方法执行结束之前，都是活的。
        
- **`long getId()`**
    
    - **作用**：获取线程的唯一标识符（ID）。
        

---

### 2. 线程控制与协作 (交通规则)

这些方法决定了线程什么时候跑，什么时候停，什么时候让路。这是**考试和面试的重灾区**。

- **`static void sleep(long millis)`**
    
    - **作用**：让当前线程“睡”一会儿（暂停执行），不释放锁。
        
    - **场景**：模拟耗时操作、定时任务、倒计时。
        
- **`void join()`** 【**必考**】
    
    - **作用**：**“插队”**。让调用这个方法的线程**等待**，直到被调用的线程执行完毕。
        
    - **通俗解释**：
        
        - 你在主线程里写了 `t1.join()`。
            
        - 意思就是：**主线程说：“t1 你先跑，我在原地等你，等你跑完了我再继续往下走。”**
            
    - **场景**：主线程需要汇总子线程的计算结果，必须等子线程算完。
        
- **`static void yield()`**
    
    - **作用**：**“礼让”**。提示 CPU 调度器：“我现在的任务不急，可以先把 CPU 让给同优先级的其他线程”。
        
    - **注意**：这只是一个**暗示**，CPU 可能会理你，也可能完全无视你（取决于操作系统）。
        

---

### 3. 优先级与守护线程 (VIP 与 后勤)

- **`void setPriority(int newPriority)`**
    
    - **作用**：设置线程优先级。
        
    - **范围**：1 (Min) 到 10 (Max)，默认是 5。
        
    - **注意**：优先级高的线程**获得 CPU 的概率高**，但并不保证一定先执行（不要依赖它写逻辑）。
        
- **`void setDaemon(boolean on)`**
    
    - **作用**：将线程标记为**守护线程 (Daemon Thread)**。
        
    - **区别**：
        
        - **用户线程**（默认）：只要还有一个用户线程在跑，JVM 就不会停止。
            
        - **守护线程**（如垃圾回收线程 GC）：是为用户线程服务的。**如果所有的用户线程都结束了，守护线程会自动死掉，JVM 退出。**
            
    - **注意**：必须在 `start()` 之前调用。
        

---

### 4. 中断机制 (优雅地停止)

- **`void interrupt()`**
    
    - **作用**：**并没有真正停止线程**，只是给线程打了一个“想让你停止”的标记（设置中断状态）。
        
    - **配合**：如果线程在 `sleep`/`wait`，会被唤醒并抛出异常；如果线程在正常跑，需要自己在 `run` 里检查 `isInterrupted()` 状态来决定是否退出。
        
- **`boolean isInterrupted()`**
    
    - **作用**：检查当前线程是否被别人打了“中断标记”。
        

---

### ⚠️ 严重警告：不要用的方法

你可能会在旧教材或老代码里看到以下方法，它们已被 **废弃 (Deprecated)**，**千万不要使用**：

- ❌ `stop()`：强行杀死线程。就像直接拔电源，可能导致数据损坏或锁无法释放。
    
- ❌ `suspend()` / `resume()`：暂停和恢复。极易导致**死锁**。
    

### 总结一张表

| **方法名**       | **静态/实例**  | **作用**             | **此时是否释放锁？**         |
| ------------- | ---------- | ------------------ | -------------------- |
| **`start()`** | 实例         | **启动**线程，由系统调用 run | -                    |
| **`run()`**   | 实例         | 线程的**执行体**，逻辑代码    | -                    |
| **`sleep()`** | **静态**     | 暂停当前线程             | **❌ 不释放**            |
| **`yield()`** | **静态**     | 礼让 CPU 时间片         | **❌ 不释放**            |
| **`join()`**  | 实例         | 等待该线程结束 (插队)       | **✅ 释放** (底层基于 wait) |
| **`wait()`**  | 实例(Object) | 等待被唤醒              | **✅ 释放**             |
