在 Java 多线程的学习中，除了刚才的语法错误（代码位置问题），在**逻辑和运行机制**上，还有 **4 个最核心的注意点**。

这些点是你运行程序时可能会感到“困惑”的源头，也是考试和面试的高频考点。

### 1. 执行顺序是“随机”的（抢占式）

这是新手最大的疑惑点。

- **现象**：你代码里先写了 `myThread.start()`，后写了 `t2.start()`。你可能会理所当然地认为：“肯定是 `myThread` 先打印完 0-9，然后 `t2` 再打印”。
    
- **真相**：**完全不一定！**
    
- **原因**：CPU 的时间片是“抢着吃”的。操作系统决定下一毫秒让谁跑。
    
- **结果**：你可能会看到这样的输出（交替出现）：
    
    Plaintext
    
    ```
    线程A: 0
    线程B: 0
    线程A: 1
    线程B: 1
    线程B: 2
    ...
    ```
    
    **注意**：不要在代码逻辑中依赖线程的执行顺序，除非你用了高级的同步手段（如 `join`, `lock` 等）。
    

### 2. `start()` vs `run()` （必考！）

虽然刚才提过了，但这里要从**原理**上再强调一次。

- **`t.run()`**：
    
    - 这只是一个**普通方法调用**。
        
    - 就像你调用 `print()` 一样，**没有**开启新线程。程序会由“主线程”跑去执行 `run` 里的代码，执行完了才回来，是**串行**的。
        
- **`t.start()`**：
    
    - 这是**魔法**所在。它会通知操作系统：“给我开辟一个新的栈空间，启动一个新的线程”。
        
    - 操作系统准备好后，会**自动**在那个新线程里调用 `run()` 方法。
        
    - 主线程调用完 `start()` 后，**不用等待**，直接继续往下走。
        

### 3. 线程是“一次性”的

- **错误操作**：
    
    Java
    
    ```
    MyThread t1 = new MyThread();
    t1.start(); // 第一次启动，正常
    // ... 等它跑完 ...
    t1.start(); // ❌ 报错！
    ```
    
- **后果**：会抛出 `IllegalThreadStateException` 异常。
    
- **规则**：一个线程对象的生命周期只有一次。跑完了就**死掉**（Terminated）了。如果你想再跑一次，必须 `new` 一个新的对象。
    

### 4. 主线程结束了，程序会停吗？

- **现象**：`main` 方法里只有几行代码，瞬间就运行完了，打印了“我是主线程”。但是你的子线程还在循环打印数字。
    
- **规则**：Java 程序的原则是 **“所有非守护线程（用户线程）都结束了，JVM 才会退出”**。
    
- **意味着**：哪怕 `main` 方法（主线程）已经结束了，只要你启动的 `t1` 和 `t2` 还在跑，程序窗口就不会关闭，直到它们也打印完为止。

### 建议你做一个小实验

你可以把你的代码稍微改一下，加上线程名字，多运行几次，感受一下“随机性”：

Java

```
public class Test {
    public static void main(String[] args) {
        // 线程 1
        new Thread(() -> {
            for(int i=0; i<5; i++) System.out.println("A: " + i);
        }).start();

        // 线程 2
        new Thread(() -> {
            for(int i=0; i<5; i++) System.out.println("  B: " + i);
        }).start();

        System.out.println("=== 主线程结束 ===");
    }
}
```

**可能的一次运行结果（注意主线程可能最早打印完）：**

Plaintext

```
=== 主线程结束 ===
A: 0
  B: 0
A: 1
  B: 1
A: 2
...
```
