### **一、 方法重写 (Override) 核心知识点**

1. 定义

在子类中，如果定义了一个与父类方法签名（方法名 + 参数列表）完全相同的方法，我们就说子类重写（覆盖）了父类的该方法。这是实现多态的关键。

2. 核心规则（口诀：“两同两小一大”）

这是考试和面试的重中之重，必须严格遵守：

- **两同（必须一致）**：
    
    - **方法名**必须相同。
        
    - **参数列表**必须相同。
        
- **两小（子类 <= 父类）**：
    
    - **返回值类型**：
        
        - 如果是基本数据类型（如 `int`, `void`），必须完全相同。
            
        - 如果是引用数据类型，子类重写方法的返回值类型必须是父类返回类型的**子类**（或相同）。
            
    - **抛出的异常**：子类重写方法抛出的**检查异常（Checked Exception）**范围不能比父类大（可以更小，也可以不抛出）。
        
- **一大（子类 >= 父类）**：
    
    - **访问权限**：子类重写方法的访问权限必须**大于或等于**父类方法的权限。
        
    - 权限排序：`public` > `protected` > `default (包访问权限)` > `private`
        

**3. `@Override` 注解**

- 建议在重写的方法上方加上 `@Override` 注解。
    
- **作用**：帮助编译器检查是否真的是重写。如果你手滑把方法名写错（例如 `tostring` 写成了 `toString`），加了注解编译器会直接报错，防止低级错误。

### **二、 重写的注意点 (易错陷阱)**

1. **重写 vs 重载 (Override vs Overload)**
    
    - **重写 (Override)**：父子类之间，方法签名完全一样（外壳不变，核心重写）。
        
    - **重载 (Overload)**：同一个类中（或继承关系中），方法名相同，但在**参数列表不同**（个数、类型、顺序不同）。与返回值和访问权限无关。
        
2. **私有方法不能被重写**
    
    - 如果父类方法是 `private` 的，子类定义了一个完全一样的方法，这**不是重写**，而是子类自己定义了一个全新的方法。因为父类的私有方法对子类不可见。
        
3. **静态方法不能被重写**
    
    - 如之前所述，静态方法只能被**隐藏 (Hide)**。父子的静态方法各玩各的，调用时看引用类型（静态绑定）。
        
4. **构造方法不能被重写**
    
    - 构造方法名必须与类名相同，子类类名与父类不同，所以构造方法根本无法重写。
        
5. **`final` 方法不能被重写**
    
    - `final` 的含义就是“最终的、不可改变的”，修饰方法时即禁止子类篡改。

#### **题目 1：重写规则判断**

已知父类定义如下：

Java

```
class Father {
    protected Number doSomething(int a) throws Exception {
        return 0;
    }
}
```

下列哪一个在子类 `Son` 中的定义是**合法的方法重写**？

A. private Number doSomething(int a) { return 1; }

B. public Integer doSomething(int a) { return 1; }

C. protected Object doSomething(int a) { return "abc"; }

D. public Number doSomething(int a, int b) { return 1; }

> **解析**：
> 
> - A 错误：权限变小了（private < protected）。
>     
> - **B 正确**：权限变大了（public > protected），返回值变小了（Integer 是 Number 的子类），异常变小了（不抛异常），方法签名一致。
>     
> - C 错误：返回值变大了（Object 是 Number 的父类）。
>     
> - D 错误：参数列表不同，这是**重载 (Overload)**，不是重写。
>

#### **题目 2：私有方法的陷阱**

阅读下列代码，输出结果是什么？

Java

```
class Base {
    private void show() {
        System.out.println("Base show");
    }
    public void print() {
        show(); // 在这里调用 show()
    }
}

class Derived extends Base {
    // 这不是重写，因为父类 show 是 private
    public void show() {
        System.out.println("Derived show");
    }
}

public class Test {
    public static void main(String[] args) {
        Base b = new Derived();
        b.print(); 
    }
}
```

A. Base show

B. Derived show

C. 编译报错

D. 运行时异常

> 解析：选 A。
> 
> 这是一个非常经典的坑。
> 
> 1. `b.print()` 调用的是父类的 `print()` 方法（因为子类没重写 `print`）。
>     
> 2. 在父类 `Base` 的 `print()` 方法中调用了 `show()`。
>     
> 3. 虽然实际对象是 `Derived`，但父类的 `show()` 是 `private` 的。**私有方法是静态绑定的**，编译器在编译 `Base` 类时，就确定了 `show()` 只能调用 `Base` 自己的版本，不可能发生多态调用子类的版本。
>

#### **题目 3：重载与重写的混合**

Java

```
class A {
    public void method(A a) {
        System.out.println("A and A");
    }
}

class B extends A {
    // 重写了父类的 method(A a)
    public void method(A a) {
        System.out.println("B and A");
    }
    // 重载了 method，参数是 B
    public void method(B b) {
        System.out.println("B and B");
    }
}

public class Test {
    public static void main(String[] args) {
        A a = new B(); // 多态引用
        B b = new B();
        
        a.method(b); // 关键行
    }
}
```

输出结果是：

A. A and A

B. B and A

C. B and B

D. 编译报错

> **解析**：**选 B**。
> 
> 1. **编译阶段（看左边）**：`a` 的类型是 `A`。编译器去 `A` 类里找，发现只有 `method(A a)` 这个方法。虽然参数传入的是 `b`（B类型），但 B 也是 A，所以匹配成功。编译器绑定的是 `A.method(A a)` 这个签名。**注意：编译器看不到子类特有的 `method(B b)` 方法**。
>     
> 2. **运行阶段（看右边）**：实际对象是 `B`。JVM 发现 `B` 类**重写**了 `method(A a)`。
>     
> 3. 结果：执行 B 类重写后的逻辑 method(A a)，输出 "B and A"。
>     
>     （提示：如果 a 是 B 类型的引用 B a = new B()，结果就会是 "B and B" 了）。
>

### 1. 只有这一种情况是“动态绑定”：

- **普通实例方法（Instance Method）**：且满足以下条件：
    
    - 非 `static`（不是静态的）
        
    - 非 `private`（不是私有的）
        
    - 非 `final`（不是最终的）
        
    - 非 构造方法
        

**只有**这种方法，JVM 才会去检查堆内存里那个**实际对象**（new 出来的对象）是谁，然后调用它的重写版本。这叫**“运行看右边”**。

### 2. 其他统统都是“静态绑定”：

除了上面那一种“特权阶级”，剩下的全是**编译期**就定死的（看引用的类型）：

1. **成员变量（Fields）**：无论静态还是非静态，全是静态绑定。**（看左边）**
    
2. **静态方法（Static Methods）**：属于类，不属于对象。**（看左边）**
    
3. **私有方法（Private Methods）**：子类看不见，无法重写。**（看左边）**
    
4. **Final 方法（Final Methods）**：禁止重写。**（看左边）**
    
5. **构造方法（Constructors）**：类名不同，无法重写。
    

### 总结口诀

> **“万物皆静态，唯有（普通）方法动。”**

你的理解已经抓住核心了：只要看到 `static`、`private` 或者访问的是**变量**，哪怕它 `new` 出来的是个“齐天大圣”，在编译器眼里，它也只是个“猴子”（引用类型）。
