### 核心机制：静态绑定 vs 动态绑定

这是造成变量和方法表现不同的根本原因：

- **方法（Method）是“动态绑定” (Dynamic Binding)：** Java 在运行时（Runtime）会检查内存中对象的实际类型。如果子类重写（Override）了方法，JVM 会根据“实际对象”是谁（这里是 `Son`）来调用子类的方法。这就是多态。
    
- **变量（Variable）是“静态绑定” (Static Binding)：** Java 编译器在编译阶段（Compile time），看到引用类型是 `Father`，就直接把 `f.num` 这个指令绑定到了 `Father` 类中定义的那个 `num` 变量上。编译器不管你实际对象是谁，它只认引用的类型。JVM 在运行时只是机械地执行编译器的指令。
    

### 2. 内存视角：并没有被“覆盖”

当子类定义了和父类同名的成员变量时，**并不是**像方法那样“覆盖”（Override）了父类的变量，而是发生了**“隐藏”（Hiding）**。

当你执行 `new Son()` 时，在堆内存中创建的这个对象，其实**同时包含**了两个 `num`：

1. 一个是继承自 `Father` 的 `num = 10`。
    
2. 一个是 `Son` 自己定义的 `num = 20`。
    

这两个变量在内存中是**共存**的，互不干扰。

- 当你用 `Father f` 去引用这个对象时，因为 `f` 是 `Father` 视角的引用，它只能“看到”属于 Father 的那一部分内存，也就是 `10`。
    
- 如果你用 `Son s` 去引用这个对象，它就能“看到” Son 定义的 `20`。
    

### 3. 一个形象的“制服”比喻

想象一下：

- **对象（new Son）**：是一个**陆军上将**（实际身份）。
    
- **引用（Father f）**：他为了微服私访，穿了一件**普通士兵的制服**（引用类型）。
    

现在有两种情况：

1. **访问变量（看肩章/外表）：** 你走过去看他的肩章（变量）。因为他穿着士兵的制服（引用是 Father），所以你看到的军衔是“列兵”（Father.num = 10）。这是由他穿的衣服（引用类型）决定的。
    
2. **调用方法（下命令/行为）：** 你让他“下达一个战术指令”（调用方法）。虽然他穿着士兵衣服，但他脑子里实际上是上将的思维（实际对象是 Son）。所以他一开口，说出的是上将级别的指令（执行 Son 的方法）。
