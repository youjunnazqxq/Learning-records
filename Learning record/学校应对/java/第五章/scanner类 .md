

### 1. 什么时候停止输入？（核心机制）

`Scanner` 就像一个**吃字符的机器**。根据你调用的方法不同，它的“胃口”和“停嘴”的时机也完全不同。

主要分为两类情况：

#### 情况 A：遇到“空白”就停止（最常用）

- **涉及方法**：`next()`, `nextInt()`, `nextDouble()` 等。
    
- **停止规则**：它们把**空格、Tab键、回车键**都视为“分隔符”（Delimiter）。
    
- **行为逻辑**：
    
    1. **跳过**开头的空白（它会忽略你一开始输入的空格）。
        
    2. 开始读取有效字符。
        
    3. **一碰到**下一个空白（空格或回车），立刻**停止读取**，并把刚才读到的东西返回给你。
        
    4. **注意**：那个作为停止信号的“回车符”或“空格”，它**不吃**，留在了缓冲区里。
        

> **举例**：如果你输入 `123 456` 然后回车。
> 
> - 调用 `nextInt()`：它读到 `123`，碰到后面的空格，停止。返回 `123`。
>     
> - 剩下的 `456` 还在管道里等着下一次读取。
>     

#### 情况 B：遇到“回车”才停止

- **涉及方法**：`nextLine()`。
    
- **停止规则**：它是以**行**为单位的。
    
- **行为逻辑**：
    
    1. 从当前位置开始读，不管有没有空格，全部吃进去。
        
    2. 直到碰到**换行符（回车键）**为止。
        
    3. **注意**：它会把那个“回车符”也吃掉（消耗掉），然后把回车符前面的所有内容返回给你。

### 2. Scanner 怎么使用？（标准流程）

使用 Scanner 通常遵循这“三部曲”：

Java

```
// 第一步：导入包（必须写在代码最上面）
import java.util.Scanner;

public class TestScanner {
    public static void main(String[] args) {
        
        // 第二步：创建对象（连接键盘）
        // System.in 代表标准输入流（也就是键盘）
        Scanner sc = new Scanner(System.in);

        System.out.println("请输入一个整数：");
        
        // 第三步：调用方法获取数据
        // 程序运行到这行会“卡住”（阻塞），直到你在控制台输入并回车
        if (sc.hasNextInt()) { // 为了安全，可以先判断是否有整数
            int num = sc.nextInt();
            System.out.println("你输入的是：" + num);
        }

        // 第四步：关闭（好习惯，虽然不写通常也不报错）
        sc.close();
    }
}
```

### 3. 它有哪些常用方法？

你可以把 `Scanner` 的方法分为三类：

#### A. 获取基本数据类型（遇到空格/回车停止）

- `nextInt()`: 读取整数（最常用）。
    
- `nextDouble()`: 读取小数。
    
- `nextBoolean()`: 读取 `true` 或 `false`。
    
- `next()`: 读取一个字符串（**但不包含空格**，比如输入 "Hello World"，它只读到 "Hello"）。
    

#### B. 获取整行（遇到回车停止）

- `nextLine()`: 读取一整行字符串（包含中间的空格）。
    

#### C. 判断输入类型（用于防止报错）

这些方法返回 `boolean`，用来在读取前先看看管道里有没有我们要的东西，防止程序崩溃。

- `hasNextInt()`: 判断下一个是不是整数？
    
- `hasNextDouble()`: 判断下一个是不是小数？
    
- `hasNext()`: 判断还有没有东西可读？

### ⚠️ 新手必踩的一个“大坑”

这是如果你现在不注意，明天写作业一定会遇到的 Bug：

**不要混用 `nextInt()` 和 `nextLine()`！**

如果你先读了一个整数，紧接着想读一行字符串：

Java

```
System.out.print("输入年龄: ");
int age = sc.nextInt(); // 假设输入 18 然后回车

System.out.print("输入姓名: ");
String name = sc.nextLine(); // 灾难发生！
```

**后果**：

- 程序根本不会让你输入姓名，直接跳过了！
    
- `name` 会变成一个空字符串 `""`。
    

**原因**：

1. 你输入 `18` + `[回车]`。
    
2. `nextInt()` 很老实，只拿走了 `18`，**把 `[回车]` 留在了管道里**。
    
3. 接下来的 `nextLine()` 一看：“哎？管道里第一个字符就是 `[回车]`，说明这一行结束了嘛！”
    
4. 于是 `nextLine()` 读到了空内容，任务结束。
    

解决方法：

在 nextInt() 后面多加一句 nextLine() 专门用来“吃掉”那个残留的回车。

Java

```
int age = sc.nextInt();
sc.nextLine(); // 专门用来吃掉那个回车符，不存任何变量
String name = sc.nextLine(); // 现在可以正常输入了
```


在使用 `Scanner` 时，确实有几个非常容易踩的“坑”。如果你能避开这几个点，你的代码就会比大部分初学者健壮得多。

以下是 `Scanner` 使用时的 **4 个核心注意点**：

### 1. 最著名的“回车符残留”问题（必考）

这是新手崩溃率 100% 的问题。

- **现象**：当你先用 `nextInt()`（或 `nextDouble()` 等）读取数字，紧接着用 `nextLine()` 读取字符串时，字符串输入会被直接跳过。
    
- **原因**：`nextInt()` 只拿走了数字，把用户按下的 **回车键 (`\n`)** 留在了缓冲区。接下来的 `nextLine()` 一看缓冲区里有回车，以为读完了一行空行，于是直接结束。
    
- **解决方案**：在读取数字后，**手动加一句 `nextLine()`** 把那个回车吃掉。
    

Java

```
// ❌ 错误写法
int age = sc.nextInt();
String name = sc.nextLine(); // 这里的 name 会变成空字符串

// ✅ 正确写法
int age = sc.nextInt();
sc.nextLine(); // 【关键】专门吃掉剩下的回车符
String name = sc.nextLine(); // 现在可以正常输入了
```

### 2. 输入类型不匹配 (InputMismatchException)

- **现象**：你写了 `sc.nextInt()`，结果用户顽皮，输入了 "abc" 或者 "12.5"。
    
- **后果**：程序直接崩盘，抛出 `InputMismatchException` 异常。
    
- **解决方案**：
    
    - **方法A（推荐）**：先判断，再读取。使用 `hasNextInt()`。
        
    - **方法B**：用 `try-catch` 包裹。
        

Java

```
System.out.print("请输入年龄：");
// 先看看管道里下一个是不是整数
if (sc.hasNextInt()) {
    int age = sc.nextInt();
    System.out.println("年龄是：" + age);
} else {
    System.out.println("输入错误！请输入整数！");
    // 注意：如果输入错误，那个错误的字符还在管道里
    // 需要用 next() 把脏数据读走，否则会死循环
    sc.next(); 
}
```

### 3. 不要随便关闭 System.in

- **注意**：当你使用 `new Scanner(System.in)` 时，你是在读取标准输入流（键盘）。
    
- **风险**：如果你调用了 `scanner.close()`，它不仅关闭了 Scanner，**还会顺手把 System.in 也关了**。
    
- **后果**：在同一个程序的后面，如果你又 `new` 了一个新的 `Scanner` 想再读键盘，会报错（因为 `System.in` 已经关闭了，且无法重新打开）。
    
- **建议**：
    
    - 如果是 **文件操作** (`new File(...)`)：**必须关闭**。
        
    - 如果是 **键盘操作** (`System.in`)：通常可以让它开着，或者只在 `main` 函数结束前最后关一次。不要在中间的方法里关。
        

### 4. 效率问题（算法题注意）

- **场景**：做学校作业没问题。但如果你将来去刷算法题（如 LeetCode、牛客网）或者处理几百万行的大文件。
    
- **问题**：`Scanner` 因为要做很多正则匹配和解析，**速度非常慢**。
    
- **替代**：在需要极高性能读取时（比如读取 100万个整数），通常使用 **`BufferedReader`** + `StringTokenizer`，速度会快 5-10 倍。
    

### 总结 Checklist

写代码时问自己这三个问题：

1. **刚才读了数字吗？** 如果读了，下面要读字符串吗？要的话，记得“吃回车”。
    
2. **用户会乱输吗？** 如果会，记得用 `hasNextXxx()` 检查一下。
    
3. **这是读键盘还是读文件？** 读文件一定要 `close()`，读键盘别急着关。
