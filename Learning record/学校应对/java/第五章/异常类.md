### **一、 异常 (Exception) 核心知识点**

1. 异常体系结构
    
    Java 把所有的非正常情况封装成对象。所有的异常根父类是 java.lang.Throwable。
    
    它分两大派系：
    
    - **Error (错误)**：JVM 系统级别的严重问题（如 `OutOfMemoryError` 内存溢出）。**不可治愈**，程序通常无法处理，只能尽量避免。
        
    - **Exception (异常)**：程序运行中出现的问题。**可治愈**，程序可以通过代码进行捕获处理。
        
2. **Exception 的分类 (重中之重)**
    
    - **编译时异常 (Checked Exception)**：
        
        - **特点**：编译器“查岗”。如果你不处理，编译直接报错，程序跑都跑不起来。
            
        - **例子**：`IOException`, `SQLException`, `FileNotFoundException`。
            
        - **应对**：必须用 `try-catch` 捕获，或者用 `throws` 声明抛出。
            
    - **运行时异常 (Runtime Exception / Unchecked)**：
        
        - **特点**：编译器“放行”。编译时不出错，运行时才炸。通常是因为代码逻辑写得烂。
            
        - **例子**：`NullPointerException` (空指针), `ArrayIndexOutOfBoundsException` (数组越界), `ArithmeticException` (除以0)。
            
        - **继承关系**：继承自 `RuntimeException` 的都是运行时异常。
            
3. **处理异常的 5 个关键字**
    
    - **`try`**：可能出问题的代码块。
        
    - **`catch`**：捕获异常，进行处理（补救）。
        
    - **`finally`**：**一定会被执行**的代码块（通常用于关闭资源，如关闭文件、数据库连接）。
        
    - **`throw`**：(动词) 在方法**内部**，手动抛出一个异常对象。
        
    - **`throws`**：(名词/声明) 在方法**签名**上，声明这个方法可能会抛出什么异常给调用者。
        

---

### **二、 异常的注意点 (Attention Points)**

1. **多重 Catch 的顺序陷阱**
    
    - 如果 try 块中可能抛出多种异常，可以使用多个 catch。
        
    - **规则**：**先抓子类，后抓父类**。
        
    - 如果你把 `catch (Exception e)` 放在第一个，那么后面具体的 `catch (IOException e)` 就永远抓不到（因为多态，Exception 全都收了），编译器会报错“代码不可达”。
        
2. **重写方法时的异常限制 (结合继承)**
    
    - 这也是“两小一大”规则中的**“一小”**。
        
    - **规则**：子类重写父类方法时，子类抛出的**编译时异常**（Checked Exception），**不能比父类更多或更广**。
        
    - _比喻：父亲说“我这辈子可能会欠 1 万块钱（异常）”，儿子继承父亲，不能说“我可能会欠 1 个亿”。儿子只能欠得更少（不抛异常），或者欠具体的（抛出父类异常的子类）。_
        
    - **注意**：如果父类方法没有抛出异常，子类重写时**绝对不能**抛出编译时异常（但可以抛出运行时异常）。
        
3. **`finally` 的“霸道”**
    
    - `finally` 块中的代码几乎在任何情况下都会执行，即使 try 或 catch 中有 `return` 语句。
        
    - **深坑**：如果在 `finally` 中写了 `return`，它会**覆盖**掉 try/catch 中的 `return`。
        
4. **`throw` vs `throws`**
    
    - `throw`：写在方法里，抛出一个**对象**。 `throw new Exception("错了");`
        
    - `throws`：写在方法名后面，声明一个**类名**。 `void method() throws Exception {}`

`throw` 是 Java 中处理异常时的一个**动词**（动作）。

简单来说，它的作用是：**在方法内部，手动产生并抛出一个异常对象。**

你可以把它想象成：**“报警”或者“亮红牌”**。当程序运行到某个地方，发现数据不对劲或者逻辑走不通了，程序员可以使用 `throw` 主动停止当前流程，把问题抛出去。

---

### 1. 核心作用详解

1. 制造异常：
    
    通常异常是 JVM 自动发现的（比如除以 0，JVM 会自动抛出 ArithmeticException）。但有时候，逻辑上的错误 JVM 是看不出来的（比如年龄被设置成了 -100 岁）。这时候就需要你用 throw 手动制造一个异常。
    
2. 中断程序：
    
    throw 语句一旦执行，后面的代码就不会执行了（类似于 return）。程序会立即跳到最近的 catch 块，或者把异常甩给上一级调用者。
    

### 2. 代码示例：为什么要用它？

假设你在写一个设置年龄的方法，`int` 类型本身是可以存负数的，但作为年龄是不合法的。

Java

```
public void setAge(int age) {
    if (age < 0) {
        // 这里的逻辑是：数据不合法，我拒绝继续运行，并把问题甩出去
        // 语法：throw new 异常类名("错误提示信息");
        throw new IllegalArgumentException("年龄不能为负数！"); 
    }
    
    // 如果上面 throw 了，这行代码永远不会执行
    this.age = age; 
}
```

### 3. 最容易混淆的点：`throw` vs `throws`

这是考试和面试中**必考**的区别，一定要分清：

|**关键字**|**throw (单数)**|**throws (复数)**|
|---|---|---|
|**位置**|在**方法体内部**|在**方法名后面** (方法声明处)|
|**词性**|**动词** (动作)|**名词** (声明/预警)|
|**作用**|**真的抛出了**一个异常对象|**声明**该方法**可能**会抛出异常，提醒调用者注意|
|**后面跟什么**|跟**异常对象** (`new Exception()`)|跟**异常类名** (`Exception.class`)|
|**数量**|每次只能抛出**一个**对象|可以声明**多个**类名 (逗号隔开)|

**一句话记忆：**

> 你在方法头**贴告示 (`throws`)** 说“这里可能有狗”，如果真的有狗咬人了，你就**把狗扔 (`throw`)** 出来。
