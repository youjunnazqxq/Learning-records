### **一、 抽象类 (Abstract Class) 核心知识点**

1. **定义**
    
    - 使用 `abstract` 关键字修饰的类称为**抽象类**。
        
    - 使用 `abstract` 关键字修饰，且**没有方法体**（没有大括号 `{}`，直接以分号结束）的方法称为**抽象方法**。
        
2. **核心作用**
    
    - **模版设计**：抽象类本质上是一种“模版”或“规范”。它定义了一组子类必须实现的功能（抽象方法），但自己不提供具体的实现逻辑。
        
    - **强制约束**：它强制要求子类必须重写某些方法，否则子类也必须声明为抽象类。
        
3. **语法规则**
    
    - **声明类**：`public abstract class Animal { ... }`
        
    - **声明方法**：`public abstract void eat();` // 注意没有 {}
        
4. **继承关系**
    
    - 如果一个类继承了抽象类，它必须**实现（重写）**父类中**所有的**抽象方法。
        
    - 如果子类没有完全实现父类的所有抽象方法，那么子类自己也必须被声明为**抽象类**。
        

---

### **二、 抽象类的注意点 (Attention Points)**

1. **“有抽象必抽象”**
    
    - 如果一个类中包含了**至少一个**抽象方法，那么这个类**必须**被声明为抽象类。
        
    - 反之，一个抽象类中**可以没有**任何抽象方法（这样做通常是为了禁止该类被实例化）。
        
2. **不能实例化**
    
    - 抽象类**不能使用 `new` 关键字创建对象**（例如 `Animal a = new Animal();` 是错误的）。
        
    - **但是**，抽象类可以作为引用变量的类型，指向非抽象子类的对象（多态），例如 `Animal a = new Dog();`。
        
3. **构造方法依然存在**
    
    - 虽然抽象类不能实例化，但它**有构造方法**。这些构造方法是给子类用的，子类在初始化时（`super()`）会调用父类构造器来初始化父类定义的属性。
        
4. **`abstract` 关键字的“死对头”**
    
    - `abstract` 不能和 `final` 共存：`final` 禁止继承/重写，`abstract` 强制继承/重写，逻辑冲突。
        
    - `abstract` 不能和 `private` 共存：`private` 子类看不见，无法重写。
        
    - `abstract` 不能和 `static` 共存：`static` 方法属于类，不参与多态重写。
        

---

抽象类（Abstract Class）是 Java 面向对象中非常重要的概念，它介于“普通类”和“接口”之间。你可以把它想象成**一份“半成品”的设计图纸**。

以下是学习和使用抽象类时必须掌握的**核心注意点**（也是考试和面试的常考点）：

### 1. 核心规则：不能直接实例化

- **规则**：你**不能**使用 `new` 关键字来创建抽象类的对象。
    
- **原因**：抽象类中可能包含未实现的“抽象方法”（只有名字没有代码体），如果允许创建对象，调用这个空方法就会出错。
    
- **用法**：它必须被**子类继承**，通过实例化子类来使用。
    
    Java
    
    ```
    AbstractParent obj = new AbstractParent(); // ❌ 编译报错
    AbstractParent obj = new ConcreteChild();  // ✅ 正确，多态写法
    ```
    

### 2. 方法与类的关系（重点）

这里有一个包含逻辑关系的口诀：

- **有抽象方法的类，必须是抽象类。** (一旦类里有一个方法没写完，整个类就是“半成品”)。
    
- **但是，抽象类里可以没有抽象方法。** (哪怕所有方法都写完了，我依然可以声明它是 abstract，目的是为了不让别人直接 `new` 它，强制要求继承)。
    

### 3. 子类的义务

如果一个普通类（非抽象类）继承了抽象类，它**必须重写（实现）父类中所有的抽象方法**。

- **如果不实现怎么办？** 那么这个子类也必须被声明为 `abstract`。
    

### 4. 关键字冲突（考试高频点）

`abstract` 关键字不能和以下关键字同时修饰**同一个方法**，因为逻辑互斥：

- **`private`**: 抽象方法是为了让子类重写的，如果是 `private`，子类看不见，无法重写。
    
- **`final`**: `final` 表示“不可改变/不可重写”，这与 `abstract`（必须被重写）完全矛盾。
    
- **`static`**: `static` 方法属于类，可以直接通过类名调用。如果允许 `static abstract`，用户通过 `类名.方法()` 调用一个空方法，毫无意义且危险。
    

### 5. 构造器（容易误解的点）

- **问题**：抽象类不能被实例化，那它有构造器（Constructor）吗？
    
- **答案**：**有！**
    
- **作用**：虽然你不能 `new` 抽象类，但当子类实例化时，**子类的构造器会首先调用父类的构造器**（`super()`），用于初始化父类中定义的成员变量。
    

### 6. 代码示例

让我们用一个简单的例子把上面的点串起来：

Java

```
// 1. 使用 abstract 关键字
abstract class Animal {
    String name;

    // 5. 抽象类有构造器，供子类初始化使用
    public Animal(String name) {
        this.name = name;
    }

    // 普通方法：子类可以直接继承使用
    public void sleep() {
        System.out.println(name + " is sleeping.");
    }

    // 2. 抽象方法：没有方法体 {}，只有分号 ;
    // 4. 不能加 private, final, static
    public abstract void makeSound();
}

class Dog extends Animal {
    public Dog(String name) {
        super(name); // 调用父类构造器
    }

    // 3. 子类必须实现父类的所有抽象方法
    @Override
    public void makeSound() {
        System.out.println("Woof! Woof!");
    }
}

public class Main {
    public static void main(String[] args) {
        // Animal a = new Animal("Test"); // ❌ 报错：不能实例化
        Animal myDog = new Dog("Buddy");  // ✅ 多态
        myDog.makeSound(); // 输出: Woof! Woof!
        myDog.sleep();     // 输出: Buddy is sleeping.
    }
}
```

### 总结建议

在你现在的学习阶段（基于你刚才写的 GCD 代码），你只需要记住最关键的一点：

抽象类主要用于“制定标准”。父类把大致的框架搭好（比如普通方法），把不确定的、具体实现因人而异的功能留成 abstract 方法，强迫子类去填空。
