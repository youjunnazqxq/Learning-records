### **一、 接口 (Interface) 核心知识点**

**1. 定义与本质**

- **关键字**：使用 `interface` 定义接口，使用 `implements` 实现接口。
    
- **本质**：接口是一种比抽象类“更纯粹”的抽象。它本质上是一份**“契约”**或**“标准”**（比如 USB 接口标准，不管你是鼠标还是键盘，只要插得上就能用）。
    
- **核心作用**：
    
    - **解耦**：将定义与实现分离。
        
    - **多实现**：突破了 Java 单继承的限制（一个类只能 `extends` 一个父类，但可以 `implements` 多个接口）。
        

2. 接口成员的“潜规则” (默认修饰符)

在接口中，即使你不写修饰符，编译器也会自动加上（这是考试常考点）：

- **成员变量**：默认都是常量。
    
    - 隐式修饰符：`public static final`。
        
    - 必须显式初始化。
        
- **成员方法**（Java 8 之前）：默认都是抽象方法。
    
    - 隐式修饰符：`public abstract`。
        
    - _注：Java 8 引入了 `default` 和 `static` 方法，Java 9 引入了 `private` 方法，但基础教学通常侧重于抽象方法。_
        

3. 接口回调 (Interface Callback)

这听起来很高大上，其实就是多态的一种应用。

- **定义**：把“实现了接口的子类对象”赋值给“接口类型的引用变量”。
    
    - 格式：`接口名 变量名 = new 实现类();`
        
    - 例如：`USB device = new Mouse();`
        
- **回调机制**：当通过接口引用调用方法时，实际上执行的是实现类中重写后的逻辑。
    
- **场景**：广泛用于事件监听（如点击按钮）、策略模式等。即便接口不知道具体的实现类是谁，它只要调用接口方法，具体的活儿就由实现类干了。
    

---

### **二、 接口的注意点 (Attention Points)**

1. **没有构造方法**
    
    - 接口**绝对不能**有构造方法。抽象类还可以有构造方法给子类用，接口完全不需要初始化（因为它没有普通成员变量）。
        
    - 接口也不能被 `new` 实例化。
        
2. **实现类的义务**
    
    - 一个非抽象类实现接口，必须重写接口中**所有**的抽象方法。少一个都不行，否则该类必须声明为抽象类。
        
3. **多继承关系**
    
    - **类与类**：单继承 (`extends`)。
        
    - **类与接口**：多实现 (`implements A, B`)。
        
    - **接口与接口**：**多继承** (`interface A extends B, C`)。是的，接口之间可以多继承！
        
4. **接口回调 vs 指针**
    
    - 在 C 语言中，回调通常通过函数指针实现。在 Java 中，我们没有指针，而是通过**接口引用**指向**对象**来实现回调。

### **总结：抽象类 vs 接口**

最后送你一个高频面试题的对比表，帮助记忆：

|**特性**|**抽象类 (Abstract Class)**|**接口 (Interface)**|
|---|---|---|
|**关系**|**Is-a** (如果不包括我，你是不完整的)|**Like-a / Can-do** (你具备某种能力)|
|**成员变量**|各种类型都可以|只能是常量 (`public static final`)|
|**构造方法**|**有**|**无**|
|**继承限制**|单继承|**多实现**|
|**设计目的**|代码复用 (模板)|行为规范 (解耦)|

如果你能分清什么时候用抽象类（比如设计一个通用的“BaseServlet”），什么时候用接口（比如设计一个“Runnable”能力），你的面向对象设计能力就入门了！
