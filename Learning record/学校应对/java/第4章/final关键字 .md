“`final`”这个单词在英语里是“最终的”、“决定性的”意思。在 Java 中，它的核心含义就是**“不可改变”**或者**“到此为止”**。

如果说 `abstract`（抽象）代表“**没做完，你必须接着做**”，那么 `final` 就代表“**做完了，谁也不许改**”。它们两个在某种程度上是**死对头**。

我将从**变量**、**方法**、**类**这三个维度，带你彻底搞懂它。

---

### 1. `final` 的三大用法

#### ① 修饰变量：变成了“常量”

当你在变量前面加上 `final`，这个变量就变成了**常量**。

- **规则**：一旦赋值，**终生**不能修改。
    
- **场景**：通常和 `static` 一起使用，用来定义全局常量（如圆周率）。
    
    - `static final double PI = 3.1415926;`
        

Java

```
class Test {
    void method() {
        final int x = 10;
        // x = 20; // ❌ 报错！因为x已经是最终值，不能改了
        
        System.out.println(x); // ✅ 可以读取，不能写入
    }
}
```

#### ② 修饰方法：禁止“篡改”

当你在方法前加上 `final`，子类可以继承使用它，但**不能重写（Override）**它。

- **规则**：父类说：“这个方法的逻辑我已经定死了，必须要按我说的做，子类不许自作聪明去修改。”
    
- **场景**：为了安全或算法的稳定性（比如 Java 中的 `Object.getClass()` 方法就是 final 的）。
    

Java

```
class Father {
    final void secureLogin() {
        System.out.println("安全验证通过");
    }
}

class Son extends Father {
    // void secureLogin() { ... } // ❌ 报错！你不能重写父类的final方法
}
```

#### ③ 修饰类：断子绝孙

当你在类名前加上 `final`，这个类就**不能被继承**了。

- **规则**：这个类是完美的/封闭的，不需要子类去扩展它。
    
- **场景**：Java 中最著名的例子就是 `String` 类。Java 不希望你创造一个 `MyString` 来继承并修改字符串的核心行为。
    

Java

```
final class Boss {
    // ...
}

// class Employee extends Boss { ... } // ❌ 报错！Boss类不能被继承
```

### 2. 一个必须知道的“深坑”：引用类型

这是考试和面试的重灾区。当 `final` 修饰一个**对象引用**（比如数组、自定义对象）时，**不可变的是“地址”，而不是“内容”。**

- **比喻**：你被要求**只能住在这间房子里**（地址不能变），但你可以在房子里**换家具**（内容可以变）。
    

Java

```
class A {
    public static void main(String[] args) {
        final int[] arr = {1, 2, 3};
        
        // arr = new int[]{4, 5, 6}; // ❌ 报错！不能指向新的数组对象（地址不能变）
        
        arr[0] = 99; // ✅ 允许！因为你改的是数组里面的内容，不是数组的地址
        System.out.println(arr[0]); // 输出 99
    }
}
```

---

### 3. `final` 和 `abstract` 的爱恨情仇

它们是逻辑互斥的，**永远不能同时出现**。

- `abstract` 说：**“我没写完，子类你必须重写这个方法！”**
    
- `final` 说：**“我写完了，子类你绝对不能重写这个方法！”**
    

如果你写 `abstract final void method();`，编译器会直接把你“骂”回来，因为这对子类来说是自相矛盾的命令。
