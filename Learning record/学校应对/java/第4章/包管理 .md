
### 1. 为什么需要包？（生活中的痛点）

想象一下，你和你的同事都在开发一个大型游戏。

- 你写了一个类叫 `Hero`（英雄）。
    
- 你的同事也写了一个类叫 `Hero`。
    
- 当你把两个人的代码合并不在一起时，电脑就懵了：**“你到底要调用哪一个 Hero？”** 这就是**命名冲突**。
    

**解决方案**：

- 把你写的 `Hero` 放在 `combat`（战斗）文件夹下。
    
- 把同事写的 `Hero` 放在 `story`（剧情）文件夹下。
    
- 这样，一个是 `combat.Hero`，一个是 `story.Hero`，互不干扰。
    

**总结：包的核心作用就是为了解决名字打架的问题，同时把功能相似的类归类存放。**

### 2. 包的语法规则

在 Java 代码中，关于包有两个最重要的关键字：`package`（我是谁）和 `import`（我要用谁）。

#### ① `package`：声明自己的户口

- **规则**：必须放在 Java 源文件的**第一行**（注释除外）。
    
- **作用**：告诉编译器，这个类属于哪个包。
    
- **惯例**：通常使用公司域名的**倒写**（如 `com.google.maps`），这样能保证全球唯一。
    

Java

```
package com.mycompany.game; // 必须在第一行！

public class Hero {
    // ...
}
```

#### ② `import`：引入别人的工具

- **规则**：如果你想用别的包里的类，必须先“导入”它。
    
- **特例**：
    
    - **同包不需要导入**：和你住在同一个文件夹里的类，直接叫名字就行。
        
    - **`java.lang` 不需要导入**：这是 Java 的核心包（包含 `String`, `System`, `Math` 等），Java 默认自动帮你导好了，所以你写 `String s = "hello"` 从来不用导包。
        

Java

```
package com.mycompany.game;

import java.util.Scanner; // 引入别人的类
import java.util.*;       // 引入java.util包下所有的类（虽然方便，但可能会降低一点编译速度或导致命名模糊）

public class Test {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in); // 用了import才能直接写 Scanner
        
        String s = "hello"; // java.lang 包下的类，无需导入
    }
}
```

### 3. 包与目录的对应关系

这一点初学者容易晕：**包名必须和文件目录结构严格对应。**

如果你声明了：

package com.study.demo;

那么你的 .java 文件必须存放在：

.../com/study/demo/ 这个目录下。

编译器在找类的时候，也是顺着这个文件夹路径去挖的。

### 4. 访问权限（包是那道“墙”）

还记得访问修饰符吗？包在其中扮演了重要的角色。

- **`private`**：只有我自己（本类）能看。
    
- **`default` (不写修饰符)**：只有**同一个包**里的邻居能看。这叫“包级私有”。
    
- **`public`**：所有包的人都能看。
    

例子：

如果你的类没有写 public，那么其他包的代码连这个类都找不到，更别说调用里面的方法了。
