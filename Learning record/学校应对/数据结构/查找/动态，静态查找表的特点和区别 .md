根据你提供的PPT图片（第八章 查找），这是一个关于数据结构中“查找”章节的经典分类。

区分**静态查找表**和**动态查找表**的核心在于：**在查找的过程中，表内的具体数据集合是否发生改变（即是否有插入和删除操作）。**

以下是详细的特点和区别对比：

### 1. 静态查找表 (Static Search Table)

- **定义特点**：
    
    - 只做“查找”操作。
        
    - 在查找过程中，**数据集合是固定的**。主要目的是为了“查询”某个特定的数据元素是否存在，或者检索其属性。
        
    - **不涉及**数据的插入（Insert）或删除（Delete）操作。
        
- **适用场景**：
    
    - 数据一旦生成就不常变动的场景（例如：查字典、查历史归档数据、查电话区号）。
        
- **PPT中对应的算法（第2点）**：
    
    - **顺序表查找 (Sequential Search)**：一个一个挨着找，效率较低。
        
    - **折半查找 (Binary Search)**：也叫二分查找，要求数据必须是**有序**的，效率高。
        

### 2. 动态查找表 (Dynamic Search Table)

- **定义特点**：
    
    - 在查找过程中，**表结构是动态变化的**。
        
    - 如果查找到该元素，可能会将其**删除**；如果没找到，可能会将其**插入**到表中。
        
    - 它的构建过程本身往往就是一个查找的过程。
        
- **适用场景**：
    
    - 数据变动频繁，需要随时添加新数据或移除旧数据的场景（例如：用户注册系统、实时订单列表）。
        
- **PPT中对应的算法（第3点）**：
    
    - **二叉排序树 (Binary Sort Tree / BST)**：这是最典型的动态查找表结构。它的特点是左子树节点值 < 根节点 < 右子树节点值，插入和查找非常方便。
        
    - (扩展知识：平衡二叉树 AVL、B树、红黑树等也属于此类)。
        

---

### 总结对比表

|**比较维度**|**静态查找表**|**动态查找表**|
|---|---|---|
|**核心操作**|仅查询 (Find/Read)|查询 + 修改 (Find + Insert/Delete)|
|**数据稳定性**|数据固定不变|数据随时可能增加或减少|
|**内存/空间**|通常是一次性分配好的连续空间（如数组）|通常需要动态分配空间（如链表、树结构）|
|**典型代表**|顺序查找、二分查找|二叉排序树 (BST)、散列表 (Hash)*|

_*注：虽然你的PPT将哈希表（Hash Table）单列为第4点，但在实际应用中，哈希表通常支持高效的动态插入和删除，常被用作动态查找表。_

一句话总结：

如果你的目的是**“只看不改”，用静态表；如果你的目的是“边查边改”**，用动态表。
