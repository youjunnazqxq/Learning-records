`git checkout` 主要有两个核心作用：

1. **切换分支或提交** (像一个电视频道切换器)。
    
2. **恢复文件** (像一个时光倒流的遥控器)。
    

---

### 1. 切换分支 (Switching Branches)

这是 `git checkout` 最常用的功能：**在不同的分支之间来回切换你的工作环境**。

当你从一个分支切换到另一个分支时，你的工作区里的文件内容会立刻更新，变成你所切换到的那个分支的样子。

**命令格式：**

Bash

```
# 切换到一个已经存在的分支
git checkout <分支名>
```

**示例：** 假设你现在在 `main` 分支，想切换到 `feature/login` 分支去继续开发新功能。

Bash

```
git checkout feature/login
```

执行后，你的项目文件夹里的代码就会变成 `feature/login` 分支的状态。

**快捷方式（创建并切换）：** 我们之前提过的，`git checkout -b <新分支名>` 可以一步到位地**创建并切换**到一个新分支。

---

### 2. 恢复文件 (Restoring Files)

这个功能用来**撤销工作区里对文件的修改**。

**重要警告**：这个操作会**丢弃**你对文件所做的、但还**没有提交**的修改，而且**无法恢复**，所以请谨慎使用！

**命令格式：**

Bash

```
# 恢复单个文件，撤销所有未提交的修改
git checkout -- <文件名>
```

**示例：** 你不小心把 `config.js` 文件改得一团糟，想把它恢复成上次提交时的样子。

Bash

```
git checkout -- config.js
```

执行后，`config.js` 文件就会立刻变回它在最近一次提交时的状态，所有乱七八糟的修改都会被丢弃。

---

### **补充：新命令 `git switch` 和 `git restore`**

因为 `git checkout` 的功能太多（既能切换分支又能恢复文件），容易让人混淆。所以从 Git 2.23 版本开始，官方推荐使用两个新的、功能更专一的命令来替代它：

- **`git switch <分支名>`**：专门用来**切换分支**。
    
- **`git restore <文件名>`**：专门用来**恢复文件**。
    

这两个新命令的意图更清晰，不容易误操作。虽然 `git checkout` 依然能用，但推荐您开始熟悉和使用 `git switch` 与 `git restore`。
